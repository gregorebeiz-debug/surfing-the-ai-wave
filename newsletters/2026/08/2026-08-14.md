### Claude Code Auto Mode: Ya es el default — desde hoy

A partir de esta sesión — literalmente hoy 14 de agosto — Claude Code en planes Pro, Max y Team opera en **auto mode** por defecto. La promesa clásica de seguridad (el humano aprueba cada acción riesgosa) cede ante un clasificador que evalúa cada tool call en tiempo real antes de ejecutarla.

Los números detrás del cambio son reveladores: en pruebas controladas, Anthropic plantó comandos peligrosos en 1,053 sesiones. El clasificador bloqueó 937 (89%). Los revisores humanos bloquearon solo 143 (13.6%). El problema no era el sistema — era que los humanos aprobaban el 97% de todas las solicitudes de forma refleja, sin leer.

**Lo que Anthropic no resalta:** el clasificador dejó pasar 116 de 1,053 comandos peligrosos. Auto mode no es bala de plata — es mejor que la fatiga de aprobación. Para flujos con acceso a producción o datos sensibles, sigue aplicando aislamiento de contexto por tarea. El overhead del clasificador no cuenta contra tus límites de uso en Pro/Max/Team.

### MCP 2026-07-28: El protocolo se reinventa como stateless

La actualización más grande del Model Context Protocol desde su lanzamiento ya está llegando a Claude. El cambio central: MCP abandona el modelo bidireccional con estado y sesiones de inicialización para convertirse en un protocolo de request/response sin estado.

¿Qué significa en práctica? Puedes desplegar tus MCP servers en AWS Lambda, Cloudflare Workers, o cualquier edge runtime. Sin servidor persistente, sin gestión de conexiones. Scale horizontal automático detrás de cualquier load balancer.

Lo demás que trae el spec 2026-07-28:
- **MCP Apps y Tasks**: extensiones formales bajo un framework versionado — la ruta oficial para añadir UIs interactivas y trabajo de larga duración sin tocar el core del protocolo
- **Auth production-grade**: OAuth 2.0 + OIDC integrados, compatible con Entra, Okta y cualquier IdP enterprise
- SDKs oficiales (TypeScript, Python, Go, C#) ya soportan el nuevo spec; Rust en beta
- 400M+ descargas mensuales del SDK — MCP está consolidando su posición como estándar de industria

### Z.ai lanza GLM-5.3: ¿El mejor modelo de código open-source?

Zhipu AI lanzó hoy GLM-5.3 con afirmaciones agresivas: 50% de mejora en coding sobre GLM-5.2 y claims de superar a Claude Opus 4.8 en benchmarks de código usando menos tokens (31.4% vs 29.5% en SWE-Marathon, con ~38% menos output tokens por tarea). Logró esto sin reentrenar el modelo base — solo con post-training escalado.

Números en benchmarks del laboratorio:
- Terminal-Bench 3.0: 4.6 → **28.3**
- DeepSWE v1.1: 46.2 → **66.9**
- SWE-Marathon v1.1: 19.4 → **42.5**

Lo que merece análisis crítico: las capacidades de ciberseguridad "crecieron más rápido de lo anticipado" durante el entrenamiento. Z.ai reporta 84.5% en CyberGym, lo que llevó a una revisión de seguridad antes de publicar los pesos. Llegada estimada de pesos open-source: dos semanas. Vale la pena esperar — un modelo de código competitivo con Opus 4.8 pero descargable localmente es señal importante para workflows donde el costo de inferencia importa.

## 🛠️ Tool & Repo Watch — Herramientas y repos

### LiteLLM — Core migrado a Rust

LiteLLM migró su AI Gateway a Rust. Los números: 15x más throughput, 11x menos memoria, overhead sub-1ms por request. La arquitectura separa responsabilidades: el core Rust transforma datos (normaliza requests/responses, cuenta tokens, maneja streaming), el SDK Python mantiene la lógica de negocio y configuración.

**Por qué te importa:** Si usas LiteLLM para enrutar entre Claude, GPT y modelos locales en tus pipelines de automatización — esta migración reduce el overhead de infraestructura de forma significativa. La función principal que usas (call unificado a 100+ LLM APIs en formato OpenAI con cost tracking) ahora es materialmente más rápida. El core Rust está en beta y es opt-in, con fallback automático al path Python si algo falla — migración sin riesgo.

→ [GitHub: BerriAI/litellm](https://github.com/BerriAI/litellm) | [Benchmarks de rendimiento](https://docs.litellm.ai/blog/rust-ai-gateway-benchmarks) | Acción sugerida: **Monitorea la beta** — cuando salga a stable, actualiza.

### OpenClaw — El agente personal open-source con 355K stars

OpenClaw es un agente de IA self-hosted que toma acciones en tu nombre: ejecuta comandos de shell, gestiona archivos, navega la web, maneja email. Se activa por WhatsApp, Telegram o CLI. Local-first por diseño: datos y memoria quedan en tu máquina. Model-agnostic: soporta Claude, GPT, DeepSeek, Grok y modelos locales via Ollama.

Empezó como proyecto de fin de semana en noviembre 2025, cruzó 100k estrellas y 2M visitantes en una semana. Hoy: 355K+ stars — posiblemente el crecimiento más acelerado de GitHub. El creador se unió a OpenAI para liderar su división de personal agents; el proyecto pasó a fundación independiente con respaldo de OpenAI.

**Por qué te importa:** Tu stack ya incluye Claude Code + MCP para el entorno de desarrollo. OpenClaw opera en la capa opuesta: el entorno personal (mensajería, sistema de archivos, web). La combinación de ambos cubre el loop completo. **Caveat crítico:** el crecimiento meteórico ha atraído análisis de seguridad preocupantes — [uno los califica de "catástrofe de seguridad"](https://mothasa.substack.com/p/the-most-popular-ai-agent-on-github). Evalúa el repo a fondo antes de darle acceso a datos sensibles.

→ [GitHub: OpenClaw](https://github.com/petersteinberger/OpenClaw) | 355K+ stars | Acción sugerida: **Explora** con precaución.
