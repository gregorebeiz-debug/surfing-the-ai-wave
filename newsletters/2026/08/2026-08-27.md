### Claude Code: Semana de parches críticos y endurecimiento

Anthropic publicó tres versiones importantes de Claude Code esta semana. La **v2.1.245** (25 ago) corrige un crash crítico al iniciar en Linux con glibc 2.44 — afecta Arch Linux, CachyOS y Fedora Rawhide, que ya corren esa versión. La **v2.1.243** (24 ago) añade un breakdown detallado del loop de agentes para identificar cuellos de botella en sesiones largas. La **v2.1.239** (21 ago) corrige estimaciones de costo en workspaces con data-residency y extiende fullscreen a más plataformas cloud.

En paralelo, la actualización de estabilidad general incorporó: advertencias de Bash allow-rules cuando una regla podría ser demasiado permisiva, pestaña "Auto mode" en `/permissions` para gestión más rápida, mejor rendimiento en transcripts y fullscreen, y sesiones background con comportamiento más predecible.

El patrón es claro: Anthropic está en modo consolidación, no feature-drop. Claude Code ya no es un proyecto de demo — lo están construyendo para uso intensivo en producción. Para usuarios Linux en distribuciones rolling-release, el v2.1.245 es actualización inmediata.

### GPT-5.6 llega a Kiro con recorte de costos acumulado del ~82%

El 25 de agosto OpenAI integró la familia completa de **GPT-5.6** (Sol, Terra, Luna) en **Kiro**, el IDE agente de AWS. Benchmarks conjuntos en Terminal-Bench 2.1 reportan una reducción del costo por tarea completada de aproximadamente 82% vs iteraciones anteriores. GPT-5.6 Sol redujo precios de API en más del 20% por 3 meses (desde el 21 ago), sumando al recorte de Luna (–80%) y Terra (–20%) de julio.

El mismo 20 de agosto OpenAI activó **Zero Data Retention** para sus modelos frontier — un paso que quita uno de los últimos obstáculos enterprise para adoptar la API directamente sin contractos especiales de privacidad.

Lo relevante para Gregorio: esto no cambia tu workflow con Claude Code. Pero si algún cliente te pregunta por alternativas, Kiro + GPT-5.6 Sol será la propuesta estándar del ecosistema AWS. El movimiento de precios acumulado de OpenAI en julio-agosto ha sido agresivo; Anthropic no ha anunciado ajustes equivalentes en la API.

### MCP: Spec limpiada, roadmap 2026 publicado

Dos movimientos importantes en el protocolo MCP. Primero, la revisión del **28 de julio** (que solo ahora está siendo registrada ampliamente) eliminó el handshake initialize/initialized y el header `Mcp-Session-Id`, añadió el RPC `server/discover` para negociación de capacidades al conectar, reemplazó la resumibilidad SSE por un modelo de re-emisión de requests, y deprecó formalmente **Roots, Sampling, Logging** y el transporte legacy HTTP+SSE.

Segundo, el **22 de agosto** el equipo de maintainers publicó el roadmap 2026 con 5 prioridades: mensajería agente-a-agente, transporte HTTP-nativo, identidad de agentes, mejores primitivos, y polish de SDKs.

Lo relevante: si has construido clientes MCP que usan el handshake viejo, el Mcp-Session-Id, o dependen de Sampling/Roots/Logging, revisa compatibilidad. La deprecación de esas características indica que MCP está convergiendo, no expandiéndose en todas direcciones. El nuevo `server/discover` hace la negociación más limpia y predecible.

*Fuentes: [ChatForest](https://chatforest.com/guides/mcp-ecosystem-2026-state-of-the-standard/), [MCP Roadmap Explainx](https://www.explainx.ai/blog/the-new-mcp-roadmap-2026), [TechCrunch MCP](https://techcrunch.com/2026/06/30/x-now-offers-an-mcp-server-to-make-its-platform-easier-for-ai-tools-to-use/)*

## 🛠️ Tool & Repo Watch — Herramientas y repos

### OmniRoute v3.8.49 — Gateway de LLMs con soporte nativo para Claude Code

Un proxy entre Claude Code (o cualquier coding tool) y 350 proveedores de LLMs con 1,200+ modelos. La killer feature es el **quota-aware auto-fallback**: si Claude Code agota cuota, redirige automáticamente a Kimi, DeepSeek, Gemini o cualquier proveedor con cuota libre sin tocar el código del proyecto. Incluye compresión RTK+Caveman (15–95% ahorro en tokens) y soporte MCP/A2A.

**Por qué te importa:** OmniRoute corre como endpoint OpenAI-compatible — Claude Code lo acepta sin modificaciones al configurar el base URL. Directo a tu stack. Útil para sesiones largas donde la cuota de Claude Pro se presiona, para experimentar con DeepSeek o Kimi manteniendo el mismo UX de Claude Code, y para proyectos de clientes que necesitan control de costos granular. ~23.6K estrellas GitHub, MIT license.

### n8n agosto 2026 — AI Agent node reconstruido + MCP bidireccional nativo

El AI Agent node de n8n fue reescrito con soporte de tool calling en Claude, GPT-4o, Gemini, Mistral y Groq. Incluye validación de JSON schema en cada tool call — si el LLM falla el formato, n8n intercepta el error y fuerza un retry configurable. Cuatro nodos de memoria nuevos: in-memory, Redis, Postgres, Motorhead. Y lo central: **n8n puede actuar simultáneamente como MCP Client y como MCP Server**.

**Por qué te importa:** Esta es la release que une tu stack de n8n con tus agentes Claude de forma directa. Un workflow n8n puede exponer sus nodos como herramientas MCP para que Claude Code las consuma. Y n8n puede consumir cualquier MCP server del ecosistema. Eso convierte n8n en hub de orquestación real entre código, workflows y herramientas externas — no solo entre APIs. Si usas n8n + Claude Code, actualizar ahora tiene sentido claro.

[n8n Docs](https://docs.n8n.io/release-notes) | **Acción: Actualizar y configurar integración MCP**

## ⚠️ Buyer Beware — Alerta de hype

**"Más de 100,000 MCP servers disponibles"** — Glama indexa 71,000+; registros combinados llegan a 101,000. Los números son reales pero engañosos: la propia comunidad MCP reconoce que la mayoría son listados abandonados, duplicados o prototipos sin mantenimiento. El número total creció rápido porque registrarse es trivial — la calidad promedio, no.

*Consejo práctico: antes de integrar cualquier MCP server de terceros, filtra por actividad en los últimos 30 días y más de 50 estrellas. Un directorio con 100K entries sin curaduría es ruido, no ecosistema.*
