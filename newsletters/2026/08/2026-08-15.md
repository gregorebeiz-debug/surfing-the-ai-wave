### Claude Code Self-Hosted: Sessions en tu infraestructura, public beta

Con la versión **v2.1.224** (lanzada el 7 de agosto), Anthropic abrió la public beta de **self-hosted environments** para planes Team y Enterprise. Un solo comando — `claude self-hosted-runner` — convierte tus máquinas o containers en la capa de compute donde corren las sessions de Claude Code, en lugar de correr en los servidores de Anthropic.

Dos modos de operación: **Fixed** mantiene N runners permanentes con sessions distribuidas entre ellos. **On-demand** levanta un runner cuando llega trabajo y lo baja al terminar — capacidad que escala directo con demanda, sin pagar por idle. Web, mobile, desktop y Routine sessions funcionan en ambos modos. El feature está desactivado por defecto y lo activa un Owner o admin en settings.

Lo que cambia en la práctica: si tienes código propietario, tokens de red interna, o requisitos de compliance que te impedían adoptar Claude Code en modo cloud, ese bloqueador desaparece. La Compliance API ya cubre estas sessions para auditorías y eDiscovery — el flujo enterprise completo está integrado desde el día uno.

### MCP 2026-07-28: El protocolo se reescribe — stateless, OAuth hardened, extensiones formales

El mayor update al Model Context Protocol desde su lanzamiento. No es una actualización incremental: es un cambio de arquitectura.

**Lo que cambia:**
- **Stateless core**: MCP abandona el modelo bidireccional stateful. Ya no hay handshake de inicialización ni sesiones a nivel de protocolo. Los servers se pueden deployar en serverless, edge, y cualquier infraestructura que no pueda mantener conexiones permanentes. Esto resuelve el pain point más grande para adopción a escala.
- **Extensions formales (versioned framework)**: MCP Apps y Tasks ahora tienen un path oficial para añadir UIs interactivas y trabajo de larga duración sin tocar el core del protocolo. Estabilidad con extensibilidad.
- **Authorization hardening**: OAuth y OIDC con integración nativa a sistemas de identidad enterprise — Entra y Okta confirmados. Reemplaza la autenticación improvisada que plaga muchos servers actuales.
- **Multi Round-Trip Requests, header-based routing, cacheable list results**: mejoras de performance que reducen latencia en workflows agenticos complejos.

Claude está rolling out soporte activamente. Los fixes de agosto — MCP connections que colgaban 30 segundos al fallar, streams que se reopenían infinitamente, OAuth que fallaba por redirect URI mismatch — son todos consecuencia de migrar a esta especificación.

**Acción:** Si tienes MCP servers propios, revisa la [guía de breaking changes y migración](https://stacktr.ee/blog/mcp-2026-spec-changes) antes de que empiece a romperse silenciosamente en producción.

*Fuentes: [MCP Blog Oficial](https://blog.modelcontextprotocol.io/posts/2026-07-28/), [Anthropic Blog](https://claude.com/blog/bringing-mcp-2026-07-28-to-claude), [Stacktree — breaking changes](https://stacktr.ee/blog/mcp-2026-spec-changes)*

### OpenAI Ultrafast: GPT-5.6 Sol a 14× velocidad, powered by Cerebras

Desde el 14 de agosto, limited preview en la API: **GPT-5.6 Sol Ultrafast** corriendo hasta **750 output tokens por segundo** — 14× el modo Standard — mediante la alianza de OpenAI con Cerebras. Misma inteligencia que Sol Standard, radicalmente diferente hardware de inferencia.

Usos en testing durante el preview: coding, commerce, financial research, support. Sin pricing público, sin fecha de GA. Los customers del preview están mid-production.

Por qué importa más allá del número: no es un modelo nuevo. Es un cambio de paradigma sobre qué flujos agenticos son viables. Cuando un agente que esperaba 8 segundos ahora espera 0.5, los pipelines multi-step que hoy se sienten lentos se convierten en aplicaciones interactivas. La velocidad rediseña la arquitectura de los agentes que puedes buildear.

## 🛠️ Tool & Repo Watch — Herramientas y repos

### n8n — AI Assistant nativo + Agent Builder + MCP dual mode

El update de agosto de n8n llega con tres adiciones que cambian el posicionamiento del producto:

1. **AI Assistant y Agent Builder integrado**: Workflows ahora se pueden construir y depurar conversacionalmente desde la UI. Reduce la curva de entrada para flujos complejos.
2. **MCP dual mode (Client + Server)**: n8n puede consumir herramientas de cualquier servidor MCP externo **y** exponer tus propios workflows como tools invocables desde Claude Code, Cursor, o cualquier cliente MCP-compatible.
3. **JSON schema validation en tool calls**: Prevención de loops infinitos por hallucinations del LLM. Respuesta mal formateada → auto-retry antes de fallar. Problema real en producción, resuelto a nivel plataforma.

**Por qué te importa:** El MCP dual mode es el cambio más significativo. Si usas n8n como capa de automatización y Claude Code como agente de desarrollo, puedes ahora exponer tus workflows de n8n como herramientas nativas para Claude. Un agente en Claude Code puede invocar directamente tu pipeline de n8n sin APIs personalizadas ni middlewares extra. La integración que antes buildabas a mano, ahora viene nativa en ambos lados del stack.

⭐ Acción sugerida: **Actualizar y explorar** — especialmente el MCP Server mode.

### OpenClaw — Agente personal open-source, 250K+ GitHub stars

[github.com/openclaw/openclaw](https://github.com/openclaw/openclaw) — El proyecto open-source de más rápido crecimiento en la historia de GitHub (de 9K a 60K stars en días, hoy +250K). Es un asistente personal AI que actúa como gateway local conectando modelos (cloud o local via Ollama) con WhatsApp, Telegram, Slack, Discord, Signal, iMessage, y más de 50 integraciones via AgentSkills preconfigurados. Model-agnostic y privacy-first — corre en tu hardware, sin ceder datos a terceros.

**Por qué te importa:** OpenClaw es el agentic OS que conecta Claude o cualquier LLM a tus canales de comunicación reales sin arquitectura adicional. Si buildeas automation agents y quieres que operen en tus canales de Telegram o WhatsApp, los AgentSkills son un template library de facto para shell commands, file management y web automation. La Non-Profit Foundation detrás garantiza que el proyecto no sea adquirido ni monetizado silenciosamente.

⭐ Acción sugerida: **Explorar** — especialmente si Telegram o WhatsApp son parte de tus flujos de trabajo.

## ⚠️ Buyer Beware — Alerta de hype

**Todos hablan de Astra (el supuesto GPT-6). Hay que frenar el entusiasmo.**

El 1 de agosto OpenAI "anunció" Astra publicando la solución de 10 problemas abiertos de matemáticas y ciencias de la computación. El internet explotó con "GPT-6 llegó". La realidad fría: sin model card, sin pricing, sin acceso en ChatGPT, sin fecha de disponibilidad. OpenAI no ha confirmado siquiera si Astra será el GPT-6 o una versión 5.7.

El dato que contextualiza: en menos de un año, OpenAI ha lanzado 7 modelos en la familia GPT-5 sin una sola vez usar el label "GPT-6". El patrón es claro — el número de versión es marketing, no un milestone técnico. Lo que sí es real: GPT-5.6 Sol Ultrafast a 750 tok/seg. Eso sí está en producción.

Espera a ver un model card antes de re-arquitectar nada alrededor de Astra.
