### 3. MCP 2026-07-28: el spec de agentes cambió fundamentalmente

El release candidate publicado el 28 de julio es la revisión más grande de Model Context Protocol desde su lanzamiento. El cambio central: **MCP es ahora stateless a nivel de protocolo**.

Lo que desaparece: el handshake inicial de conexión, el header `Mcp-Session-Id`, el sticky routing entre requests. Lo que llega: dos nuevos headers HTTP (`Mcp-Method` y `Mcp-Name`) para routing en gateways sin inspeccionar el body; TTL en resultados (`ttlMs`, `cacheScope` al estilo HTTP Cache-Control); el framework de Extensions con Tasks y MCP Apps; hardening de autorización alineado con OAuth/OIDC; y deprecation policy formal para versiones futuras.

**El impacto práctico:** cualquier MCP server que hayas construido probablemente necesitará actualización cuando el spec final se adopte. Los SDKs beta (Python, TypeScript, Go, C#) ya están disponibles para testing ahora.

*Fuentes: [MCP Blog](https://blog.modelcontextprotocol.io/posts/2026-07-28-release-candidate/), [Microsoft Tech Community](https://techcommunity.microsoft.com/blog/appsonazureblog/mcp-just-went-stateless-%E2%80%94-what-the-2026-spec-changes-about-scaling-on-app-servic/4530222), [AWS Blog](https://aws.amazon.com/blogs/machine-learning/how-agentcore-gateway-supports-the-mcp-2026-07-28-spec/)*

## 🛠 Tool & Repo Watch — Herramientas y repos

### n8n — Agosto 2026: correcciones críticas para MCP en producción

Las actualizaciones de agosto de n8n están enfocadas en infraestructura: soporte para MCP OAuth con split-hostname (variable `N8N_MCP_BASE_URL`), persistencia de MCP Server Trigger en queue mode, mejoras de pool en Postgres durante reconexión, y mejor manejo de ejecuciones manuales sin nodo destino.

**Por qué te importa:** Si usas n8n como orquestador con MCP servers, el fix de OAuth split-hostname era un bloqueante real para deployments donde el MCP base URL difiere del webhook URL — común en setups detrás de reverse proxy. Si tienes MCP Server Triggers en queue mode, el fix de persistencia es crítico para no perder tool calls. Sin estas correcciones, los MCP integrations en n8n se comportaban de forma no determinística en producción.

→ Stars: open-source | Acción: **Actualizar si usas MCP en n8n**
→ [n8n Release Notes](https://docs.n8n.io/release-notes)

### CrewAI v1.10.1 — MCP nativo + A2A protocol en producción

La versión 1.10.1 añade soporte nativo para MCP y A2A (Agent-to-Agent protocol). Con A2A, un Crew puede delegar tareas a otro como endpoint estandarizado via JSON-RPC sobre HTTP o gRPC, con autenticación mTLS/OIDC/OAuth2. Con MCP, puede llamar a servers externos (GitHub, Slack, PostgreSQL, etc.) durante el razonamiento sin wrappers manuales.

**Por qué te importa:** Si construyes arquitecturas donde múltiples agentes necesitan comunicarse entre sí — el caso de uso más común en los pipelines de automatización que construyes — A2A resuelve la comunicación inter-agente con el mismo protocolo que usan los sistemas de Google y Anthropic. Y si ya tienes MCP servers configurados en Claude Code, ahora puedes reutilizarlos directamente desde crews de CrewAI sin duplicar configuración.

→ Stars: 45,900+ | Versión: 1.10.1 | Acción: **Explorar si construyes multi-agente**
→ [CrewAI GitHub](https://github.com/crewAIInc/crewAI)

### OpenClaw — El proyecto de software más estrellado en la historia de GitHub

Agente AI personal open-source que corre localmente e integra con las apps de chat existentes. Pasó de 0 a 355K+ estrellas en GitHub en menos de 5 meses — superando a React como el proyecto de software más estrellado en la historia de la plataforma. La arquitectura es agentica desde su núcleo: ejecuta tareas completas de inicio a fin sin intervención manual, combatiendo el "copy-paste fatigue" de los chatbots tradicionales.

**Por qué te importa:** Más allá del hype, OpenClaw es un referente de arquitectura para diseñar agentes locales. Si estás construyendo automatizaciones que eventualmente deberían correr on-premise o en dispositivos del cliente (sin depender de APIs cloud), estudiar cómo OpenClaw resolvió la integración multi-app y la ejecución autónoma es tiempo bien invertido.
