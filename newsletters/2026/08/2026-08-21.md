### Claude Code: Semana densa de actualizaciones (v2.1.232 → v2.1.237)

Anthropic empujó seis versiones de Claude Code entre el 13 y el 20 de agosto. Las más relevantes:

- **v2.1.237 (Aug 20):** Nuevo estilo de output "Concise" integrado — Claude entrega el resultado primero, sin preámbulo ni narración, manteniendo la misma profundidad de trabajo. Fix crítico: el prompt caching ya funciona correctamente en sesiones que usan un LLM gateway o base URL personalizada.
- **v2.1.236 (Aug 19):** Variable de entorno `ANTHROPIC_DEFAULT_MODEL` — fija el modelo por defecto para todas las sesiones nuevas sin necesidad de configurarlo manualmente cada vez.
- **v2.1.234 (Aug 17):** Auto-continúa la sesión automáticamente cuando se resetean los límites de uso. Protecciones más fuertes contra filtración de credenciales en commits.
- **v2.1.233 (Aug 14):** Soporte de GitLab merge requests en la vista worktree. Memory limits para comandos de build que se descontrolan.
- **v2.1.232 (Aug 13):** Menciona otra sesión Claude con `@` — clave para workflows multi-sesión donde un agente necesita referenciar el contexto de otra sesión activa.

El "Concise" mode es inmediatamente útil en pipelines de automatización donde el output verboso de Claude rompe parsers downstream o infla el context window de un agente orchestrador. El fix de prompt caching para custom gateways resuelve un bug que afectaba directamente setups con proxies corporativos.

### Anthropic marca todo el output de Claude con watermarks invisibles (desde Aug 2)

Desde el 2 de agosto, todo content generado o editado por Claude lleva marking invisible — tanto texto como archivos (C2PA para archivos). Aplica globalmente, no solo en Europa. El motivo es cumplimiento con EU AI Act Article 50(2), pero Anthropic decidió implementarlo worldwide en lugar de solo para usuarios europeos. Los modelos anteriores al 2 de agosto tienen hasta el 2 de diciembre para ser actualizados; incumplir puede costar hasta €15M o 3% del revenue global.

Lo que importa entender: el watermark sobrevive copy-paste y se aplica incluso cuando Claude solo corrige ortografía. Para uso interno no cambia operativamente nada. Pero si publicas contenido generado con Claude "como propio" para clientes o en canales públicos, ya está marcado y es detectable. Las herramientas de detección de AI en el mercado empezarán a usarlo. La industria de "AI ghostwriting invisible" tiene los días contados.

*Fuentes: [TechCrunch](https://techcrunch.com/2026/08/11/anthropic-says-it-will-watermark-text-generated-by-its-ai-models/), [The Next Web](https://thenextweb.com/news/anthropic-watermarks-claude-output-eu-ai-act-article-50), [The Register](https://www.theregister.com/ai-and-ml/2026/08/11/anthropic-pledges-to-embed-watermarks-to-help-discern-ai-slop-in-sop-to-eu/5285792)*

### MCP Spec 2026-07-28: El protocolo se vuelve stateless — cambio arquitectónico mayor

La nueva especificación MCP (release candidate 2026-07-28) cambia el core de bidireccional stateful a request/response stateless. En términos prácticos: cualquier request puede llegar a cualquier instancia detrás de un load balancer round-robin normal sin sesiones pegajosas ni sticky sessions. Método y nombre de herramienta viajan en headers HTTP (`Mcp-Method`, `Mcp-Name`), lo que permite routing y autorización a nivel de gateway directamente sobre los headers.

Adicionalmente: Enterprise-Managed Authorization ahora es estable — Anthropic, Microsoft y Okta ya lo adoptan. Un solo login para todos los MCP servers conectados. El ecosistema ya cuenta con más de 101,000 servidores en registros combinados.

Para quien construye o consume MCP servers: este cambio simplifica radicalmente el deployment en producción. Servidores stateless son más fáciles de escalar, no requieren infraestructura de sesiones, y se integran sin fricción con proxies y API gateways existentes.

*Fuentes: [MCP Blog — Release Candidate](https://blog.modelcontextprotocol.io/posts/2026-07-28-release-candidate/), [MCP Blog — Spec](https://blog.modelcontextprotocol.io/posts/2026-07-28/)*

## 🛠️ Tool & Repo Watch — Herramientas y repos

### Cloudflare Kitesurf — Browser nativo para agentes, 1/7 de la memoria de Chromium

Browser construido desde cero sobre V8 isolates en Cloudflare Workers. No es Chromium wrapeado: es un runtime para agentes que descarta todo lo que un agente no necesita (tabs, extensiones, UI visual). Usa 3-7x menos CPU y memoria que Chromium para tareas agenticas típicas (screenshots, HTML extraction, formularios). Soporta Chrome DevTools Protocol (CDP), por lo que funciona drop-in con Puppeteer y Playwright — agregar `browser=kitesurf` es todo lo que se necesita. Beta gratuita en Browser Run. Plan de open-source anunciado.

**Por qué te importa:** Si construyes agentes que navegan la web — scraping, automatización de formularios, verificación de páginas — Kitesurf reduce costo de cómputo y latencia drásticamente comparado con lanzar un Chromium completo. Directamente compatible con pipelines n8n que usen el nodo Playwright, o con cualquier agente Claude Code con herramientas de browser.

**Acción sugerida:** Explorar — si tienes Playwright en cualquier agente hoy, prueba `browser=kitesurf` esta semana.

→ [TechCrunch](https://techcrunch.com/2026/08/07/cloudflare-launches-kitesurf-a-browser-built-for-ai-agents/) | [Changelog oficial](https://developers.cloudflare.com/changelog/post/2026-08-06-kitesurf/) | [MarkTechPost análisis](https://www.marktechpost.com/2026/08/06/cloudflare-introduces-kitesurf-an-agent-first-web-browser-that-runs-entirely-in-v8-isolates-on-cloudflare-workers/)

### OpenClaw — Agente personal open-source, 210k+ estrellas GitHub

Agente AI autónomo que corre 100% local (Mac/Windows/Linux). Se conecta a WhatsApp o Telegram como interfaz y ejecuta tareas de forma autónoma: leer/redactar email, gestionar calendario, investigar, scraping. Creado por Peter Steinberger (fundador de PSPDFKit). Pasó de 9,000 a 210,000+ estrellas en GitHub en meses — uno de los proyectos de crecimiento más rápido en historia de la plataforma.

**Por qué te importa:** Representa exactamente el modelo de agente local que está ganando tracción en 2026: sin UI propia, sin servidor propio, WhatsApp como frontend. La arquitectura es relevante para cualquier agente de automatización personal que estés construyendo. Si quieres entender hacia dónde va el diseño de agentes autónomos de consumo, OpenClaw es el caso de estudio del momento.

**Acción sugerida:** Monitorear — revisar arquitectura de integración con mensajería y modelo de herramientas.

→ [GitHub](https://github.com/openclaw/openclaw) | [openclaw.ai](https://openclaw.ai/) | [DigitalOcean análisis](https://www.digitalocean.com/resources/articles/what-is-openclaw)

### Bumblebee (Perplexity AI) — Scanner de supply chain para MCP servers y dependencias

Scanner read-only que analiza dependencias npm/pip, MCP servers instalados y editor extensions (Cursor, VS Code) en busca de paquetes sospechosos, permisos inesperados o comportamiento anómalo. No requiere tokens de producción ni acceso de escritura. Desarrollado por Perplexity AI.

**Por qué te importa:** Con 101,000+ MCP servers en registros y crecimiento acelerado, el vector de supply chain attack en el ecosistema MCP es real y subestimado. Si instalas MCP servers de terceros — que casi seguro haces — Bumblebee es una capa de defensa inmediata. Especialmente importante antes de agregar cualquier MCP server nuevo a Claude Desktop o Claude Code.

**Acción sugerida:** Instalar — correr sobre tu setup actual antes del próximo MCP server que instales.
