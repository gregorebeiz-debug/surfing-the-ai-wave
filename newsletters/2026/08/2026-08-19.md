## 🌊 The Wave Today — Noticias que mueven la aguja

### MCP 2026-07-28: El protocolo se vuelve stateless

La quinta actualización del Model Context Protocol es la más grande desde su lanzamiento. El cambio central: MCP pasa de un protocolo bidireccional con estado a un modelo request/response sin estado. Esto significa que los servidores MCP ahora pueden correr en infraestructura serverless y edge sin necesidad de mantener sesiones activas. El handshake `initialize / initialized` desaparece. El header `Mcp-Session-Id` y el concepto de sesión a nivel de protocolo también. Además, OAuth 2.0 y OIDC quedan formalizados como estándar de autorización, y las extensiones de MCP Apps y Tasks pasan a un framework versionado y estable.

El ecosistema está respondiendo: MCP superó los 400 millones de downloads mensuales del SDK este año (4x vs. 2025), y Claude ya está implementando soporte. n8n también incorporó el nuevo handshake de discovery en su actualización de agosto.

**Por qué importa ahora:** Si usas servidores MCP propios — para Claude Code, para agentes, para pipelines de n8n — necesitas entender qué rompe esta migración. El cambio stateless simplifica el deploy pero rompe servidores existentes que dependen de la sesión. Revisa [stacktree.dev](https://stacktr.ee/blog/mcp-2026-spec-changes) para la lista completa de breaking changes.

### GPT-5.6: Orquestación multi-agente nativa en el Responses API

El 6 de agosto, OpenAI lanzó GPT-5.6 con actualizaciones que van más allá de un bump de capacidades. Lo relevante para builders: el Responses API ahora incluye orquestación multi-agente nativa, controles de continuidad de reasoning entre llamadas, tool calling programático mejorado, y mejor prompt caching. Además, GPT-5.6 Sol llega con un slider de "esfuerzo" que los usuarios pueden ajustar por respuesta, reemplazando el modelo Instant anterior.

En paralelo, el 10 de agosto OpenAI expandió Daybreak (su servicio de defensa cibernética) con un modelo GPT-5.6 Cyber especializado en tareas de seguridad ofensiva-defensiva.

**Por qué importa:** El Responses API con multi-agent nativo es una respuesta directa a lo que Claude Code + MCP ya ofrecen. Si evalúas OpenAI para pipelines agenticos, GPT-5.6 ahora es un competidor serio en orquestación. Si ya estás en Claude, confirma que la dirección de Anthropic es correcta — el mercado valida la apuesta.

### OpenAI Astra: Impresionante en el papel, frenado por seguridad

El 1 de agosto, OpenAI presentó Astra — su próxima familia de modelos, diseñada como sistema multi-agente para trabajo de largo horizonte: planifica, delega, revisa, y opera en background durante horas o días. El lanzamiento fue inusual: OpenAI publicó directamente diez pruebas formales de problemas matemáticos abiertos de más de una década (teoría de grupos, complejidad cuántica, geometría de alta dimensión), incluyendo la prueba de la existencia de grupos no-sóficos que Mikhail Gromov planteó en 1999.

Sin embargo, el 7 de agosto TechCrunch reportó que OpenAI frenó partes del desarrollo de Astra tras una revisión interna que determinó que el modelo alcanzó su "critical cybersecurity threshold" — es decir, puede identificar y ejecutar ataques cibernéticos contra sistemas reales bien protegidos de forma autónoma. Sin fecha de lanzamiento, sin pricing, sin acceso anunciado.

**Por qué importa (con cuidado):** Las capacidades matemáticas son señal de razonamiento profundo en sistemas multi-agente. Pero el freno por seguridad es dato importante: indica que el siguiente salto en agentes autónomos viene con restricciones de acceso serias. Para tu stack actual, esto no cambia nada hoy — sigue siendo una promesa sin fecha.

*Fuentes: [The Decoder](https://the-decoder.com/openai-announces-its-next-major-model-astra-by-dropping-ten-previously-unsolved-math-problems/), [TechCrunch](https://techcrunch.com/2026/08/07/openai-says-it-slowed-astra-model-development-over-security-concerns/)*
