### MCP 2026-07-28: El protocolo se vuelve stateless — y sí, rompe cosas

La revisión más disruptiva del Model Context Protocol desde su lanzamiento entra en vigor en cuatro días. Los cambios que debes conocer:

- **Sessions eliminadas**: adiós al handshake `initialize` y al header `Mcp-Session-Id`. Cada request llega con su propio contexto en un objeto `_meta`. Cualquier instancia del servidor puede manejarlo — sin sticky routing, sin shared session store, sin necesidad de un gateway de deep packet inspection.
- **OAuth 2.1 + OpenID Connect nativo**: la autorización se alinea con estándares enterprise reales. MCP ya no puede ser considerado un protocolo de localhost.
- **Tasks fuera del core (SEP-1865)**: el soporte para operaciones long-running sale del protocolo base y pasa a extensión. También llega MCP Apps: los servidores pueden ahora entregar interfaces HTML interactivas renderizadas en iframes sandboxed.

El ecosistema tiene más de 10,000 servidores activos y 97 millones de descargas mensuales del SDK. La RC ya está disponible — la ventana de diez semanas hasta el spec final existe exactamente para que mantenedores de SDKs y servidores validen los cambios. Si tienes MCP servers propios o dependes de terceros, revisa los breaking changes este fin de semana.

### OpenAI lanza GPT-5.6 en tres tiers + ChatGPT Work: el agente autónomo para empresa

El 9 de julio, OpenAI abrió GPT-5.6 al público en tres niveles de capacidad: **Sol** (flagship, $5 input / $30 output por millón de tokens), **Terra** (mid-range) y **Luna** (rápido y barato). Junto al lanzamiento llegó **ChatGPT Work**: un agente que acepta un objetivo, se conecta a tus apps (M365, Google Drive, Slack, Notion), descompone el trabajo en pasos y ejecuta de forma autónoma por horas — entregando un artefacto terminado: documento, spreadsheet, deck o web app. El 22 de julio, GPT-5.6 se convirtió en el modelo por defecto de Microsoft 365 Copilot.

El posicionamiento es explícito: OpenAI va por los contratos enterprise que hacen pequeño al negocio consumer. ChatGPT Work compite directamente con Claude Cowork.

**Lo que hay que saber para tu contexto:** En benchmarks de coding, Claude Sonnet 5 gana (76.7 vs 64.6 en promedio); en tareas agénticas de propósito general, GPT-5.6 Sol lleva ventaja (92 vs 81.9). En precio, Sonnet 5 es 2-3x más barato que Sol, y sigue en pricing introductorio hasta el 31 de agosto ($2 input / $10 output). Si tu prioridad es coding, agentes propios y costo operativo, Claude mantiene la ventaja. Si necesitas integración profunda con el ecosistema Microsoft, GPT-5.6 es el candidato natural.

## 🔧 Tool & Repo Watch — Herramientas y repos

### Claude Code v2.1.218 — Background `/code-review` + Artifacts con datos en vivo vía MCP

*Lanzado el 22 de julio. Tres cambios que impactan tu flujo directamente.*

**`/code-review` como subagente en background**: ya no llena tu conversación mientras revisa código. Sigues trabajando; el review aparece cuando termina. El contexto de revisión mantiene el target del stack de slash commands stacked. Útil para PRs largas donde antes tenías que esperar.

**Artifacts con MCP connectors activos en cada vista**: un dashboard publicado ahora puede llamar MCP connectors en tiempo real cada vez que alguien lo abre — muestra datos en vivo, no una foto del momento en que lo construiste. Los viewers usan sus propios connectors con sus propios permisos. Esto cambia el caso de uso de artifacts: de "reporte estático" a "mini-app con datos reales".

**`/fork` → sesión background con su propio row en `claude agents`**: el fork ahora siempre va a background. `/subtask` reemplaza el antiguo fork in-session.

**Por qué te importa:** Directo a tu uso diario de Claude Code. Si publicas artifacts (dashboards, reportes) y los conectas a herramientas reales, la feature de MCP connectors en artifacts es el cambio más significativo — convierte artifacts en apps funcionales sin necesidad de re-ejecutar la sesión.

### n8n — Preferencia por nodos MCP registry + Human-in-the-Loop por herramienta

Dos cambios relevantes en el último release de n8n:

**1. Preferencia por MCP registry nodes**: cuando el AI Agent node conecta herramientas, n8n ahora prefiere automáticamente los nodos del registry MCP si están disponibles. Si tenías workflows con herramientas conectadas manualmente, revisa que el comportamiento no haya cambiado.

**2. Human-in-the-Loop (HITL) granular**: puedes marcar herramientas específicas del agente para que requieran aprobación explícita antes de ejecutarse. El workflow no se detiene completo — solo el tool call crítico espera confirmación humana. Esto es arquitectura de agentes responsables sin overhead de diseño.

**Por qué te importa:** Si tienes n8n con agentes que tocan datos sensibles (bases de datos, email, APIs de terceros), HITL granular te da control preciso sin rediseñar el workflow. La preferencia por MCP registry nodes es también señal de que n8n y MCP están convergiendo — tus servidores MCP deberían conectarse más limpiamente a partir de ahora.

→ [Release notes n8n](https://releasebot.io/updates/n8n) | Acción: **Revisa tus agent workflows y activa HITL donde corresponda**

### Hallmark — Skill para Claude Code con 57 gates anti-slop de UI

Repo con tracción esta semana: **Hallmark** es un skill para Claude Code que ejecuta 57 "slop-test gates" más una auto-crítica pre-emisión en cada componente UI generado. Diseñado para combatir el output visual genérico que Claude produce por defecto — el Tailwind-copy-paste de siempre.

**Por qué te importa:** Si construyes interfaces con Claude Code + Vercel/Next.js y el resultado siempre parece el mismo dashboard azul corporativo, Hallmark puede ser el antídoto. El tradeoff es slowdown por las verificaciones adicionales. Evalúalo en proyectos donde el diseño diferenciado importa comercialmente, no en prototipos.
