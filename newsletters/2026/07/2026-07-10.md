## 🌊 The Wave Today — Noticias que mueven la aguja

### MCP entra en su era de producción: RC con fecha 28 de julio elimina sesiones obligatorias

El Release Candidate de la especificación MCP ya está disponible — fecha objetivo de publicación final: 28 de julio. Es la revisión más grande del protocolo desde su lanzamiento y tiene implicaciones directas para cualquier server MCP en producción:

- **Las sesiones desaparecen:** Se eliminó el handshake obligatorio de `initialize` y el header `Mcp-Session-Id`. Cualquier MCP server es ahora desplegable detrás de un load balancer round-robin sin sticky sessions — el cambio arquitectural que hacía costoso escalar servers horizontalmente.
- **Dos nuevos headers de routing:** `Mcp-Method` y `Mcp-Name` permiten que gateways y rate-limiters enruten por tipo de operación sin inspeccionar el body.
- **Caching nativo en el protocolo:** List y resource calls ahora llevan `ttlMs` y `cacheScope` para caching del lado del cliente — clientes compartidos en equipos pueden compartir respuestas de tool-list entre usuarios.
- **Dos extensiones oficiales:** MCP Apps (UIs HTML en iframes sandboxed) y una extensión Tasks rediseñada para trabajo long-running stateless.
- **Deprecados con ventana de 12 meses:** `Roots`, `Sampling` y `Logging`.

El ecosistema supera ya 5.800 servers comunitarios y 97 millones de descargas mensuales del SDK en 8 lenguajes.

Si tienes MCP servers en producción — o planeas desplegarlos — revisa el RC ahora; la comunidad empieza a migrar desde el momento en que sale la spec final.

### Claude Code 2.1.206 + Claude Cowork: dos releases en 48 horas

**Claude Code 2.1.206** cierra un ciclo de tres releases en tres días (2.1.203 → 2.1.206). Los fixes que importan para builders de agentes y pipelines automatizados:

- OAuth MCP servers ya no exigen re-autenticación manual tras un token refresh fallido
- `--mcp-config` y `request_timeout_ms` en `.mcp.json` ya no se ignoraban silenciosamente — eran bugs que hacían indetectable por qué un server no respondía
- Background agents ahora heredan el `PATH` correcto del daemon
- `CLAUDE_CODE_EXTRA_BODY` ya no se descarta en workers en background
- Nuevo `/doctor` que audita tu `CLAUDE.md` en busca de contenido sobredimensionado
- Working directories adicionales ahora se exponen a MCP servers vía `roots/list`
- El binario de auto-update hace streaming a disco, reduciendo memoria pico en ~400 MB

Estos bugs podían romper silenciosamente un pipeline multi-agente. Si tienes MCP servers con OAuth, configuraciones custom de timeout, o agentes en background: actualiza antes de debuggear cualquier otra cosa.

**Claude Cowork** se lanzó ayer en web y mobile — el mismo día exacto que OpenAI lanzó ChatGPT Work. Features relevantes para builders: sesiones, archivos y tareas en background que siguen al usuario entre dispositivos; mobile approvals para acciones agénticas; espacios compartidos de chat y proyectos. La competencia por el layer de colaboración empresarial es explícita.

### GPT-5.6 público: Sol, Terra, Luna — un modelo de precios que cambia el cálculo de costo para agentes

Tras dos semanas restringido a socios de confianza por petición del gobierno de EE.UU., OpenAI liberó ayer los tres modelos de GPT-5.6:

| Modelo | Input | Output | Perfil |
|--------|-------|--------|--------|
| **Sol** | $5/M | $30/M | Reasoning frontier |
| **Terra** | $2.50/M | $15/M | Tareas diarias (2x más barato que Sol) |
| **Luna** | $1/M | $6/M | Velocidad y volumen |

Junto con los modelos llegó el nuevo sistema de prompt caching de OpenAI: breakpoints explícitos (no automáticos como Anthropic), TTL mínimo de 30 minutos, descuento del 90% en cache reads.

Para loops agénticos de alto volumen, Luna + caching agresivo puede llevar el costo por llamada a valores prácticamente despreciables. Terra es la opción racional para agentes conversacionales en producción. Sol compite directamente con Fable 5 en el tier de reasoning frontier.

*Fuente: [CNBC](https://www.cnbc.com/2026/07/08/openai-expanding-gpt-5point6-ai-model-release-ending-government-limits.html)*
