### Claude Sonnet 5 es el nuevo default — y cambia lo que Claude Code puede hacer hoy

Anthropic lanzó Claude Sonnet 5 el 30 de junio y lo activó como modelo por defecto para usuarios Free y Pro el 1 de julio. Lo que importa: **también es el nuevo default en Claude Code**, con ventana de 1M tokens y *adaptive thinking* activado por defecto.

Los números son concretos: 80.4% en Terminal-Bench 2.1 vs. 67% de Sonnet 4.6 — 13 puntos de mejora en tareas multi-paso. Los early testers reportan que completa workflows que antes se atascaban, y revisa su propio output sin que se lo pidan. Cybersecurity safeguards activados por defecto (primera vez para un modelo Sonnet). Pricing introductorio: $2/$10 por millón de tokens hasta el 31 de agosto (luego sube a $3/$15).

El framing de Anthropic es explícito: "la guerra de la IA se está moviendo de chat a agentes." Sonnet 5 es su apuesta de que el mid-tier puede ejecutar lo que antes requería Opus.

### GPT-5.6: Sol, Terra y Luna — el próximo modelo de OpenAI, pero no para ti todavía

OpenAI presentó su familia GPT-5.6 con tres modelos: **Sol** (flagship, $5/$30 por millón), **Terra** (balanceado, $2.50/$15), y **Luna** (económico, $1/$6). Sol corre sobre Cerebras a hasta 750 tokens/segundo. En benchmarks, Sol es su modelo más capaz hasta la fecha en software engineering, computer use y cybersecurity.

El dato que cambia todo: **acceso restringido a ~20 organizaciones vetadas por el gobierno de EE.UU.** mientras se completan revisiones de seguridad nacional. OpenAI no ha dado fecha concreta para disponibilidad general. Adicionalmente, la empresa propone dar al gobierno federal un 5% de participación — parte de un arreglo más amplio con los principales labs de IA de EE.UU.

Relevante geopolíticamente. Operativamente irrelevante para desarrollo independiente hoy.

## 🔬 Deep Dives — Vale la pena explorar directamente

### Claude Code — Cambios de comportamiento por defecto que rompen workflows existentes

El changelog de las últimas semanas acumula actualizaciones que **cambian comportamiento por defecto** — no mejoras silenciosas:

- **Modo Manual como nuevo default:** `AskUserQuestion` ya no auto-continúa. El agente espera aprobación explícita. Opt-in a idle timeout via `/config`. Si tenías workflows de background que asumían auto-continuación, se rompen.
- **MCP auth desde CLI:** Nuevos comandos `claude mcp login <n>` y `claude mcp logout <n>` para autenticar servidores MCP sin abrir el menú `/mcp`. Soporta `--no-browser` para completar auth por SSH — útil para setups remotos.
- **Timeout en MCP tools colgadas:** Remote MCP tool calls que no respondían podían bloquear indefinidamente. Ahora abortan con error después de un tiempo configurable (`CLAUDE_CODE_MCP_TOOL_IDLE_TIMEOUT`).
- **Glob patterns en deny rules:** `"*"` en posición de tool-name deniega todos los tools. Permite reglas de permisos más expresivas.
- **Session names legibles:** Las sesiones tienen nombres por defecto al iniciar, más fáciles de identificar y referenciar vía `SendMessage`.
- **JetBrains flickering fix:** Resuelto el parpadeo en IntelliJ/PyCharm/WebStorm 2026.1+.

**Por qué explorar:** El cambio a modo Manual es el más disruptivo — revisa tus hooks y configuraciones antes de asumir que los flujos de agente siguen igual. El nuevo auth de MCP por CLI simplifica setups SSH significativamente.

[Ver changelog completo](https://code.claude.com/docs/en/changelog)

## 🛠️ Tool & Repo Watch — Herramientas y repos

### OpenWiki — CLI que escribe y mantiene tu CLAUDE.md automáticamente

[OpenWiki](https://github.com/langchain-ai/openwiki) (LangChain) es un CLI que genera y mantiene documentación de tu codebase orientada a agentes. Se instala con `npm install -g openwiki`, se inicializa con `openwiki --init`, y lee tu repo para generar documentación estructurada.

**Por qué te importa:** Hace append directo a tu `CLAUDE.md` o `AGENTS.md` con instrucciones para que Claude Code referencie la documentación cuando busca contexto. Si manejas repos con arquitecturas complejas donde Claude Code pierde el hilo, esto ataca el problema desde la raíz — contexto estructurado, no prompts más largos. Incluye GitHub Action para PRs automáticos diarios de actualización de documentación. Soporta OpenRouter, OpenAI y Anthropic como backends.

**Acción sugerida:** Instalar — probar en un repo mediano antes de escalar a producción.

---

### alibaba/page-agent — GUI agent en JavaScript puro, cero dependencias

[page-agent](https://github.com/alibaba/page-agent) de Alibaba es un agente GUI que vive dentro de la página web — sin extensión de browser, sin Python, sin headless browser. JavaScript puro inyectado en página que controla interfaces con lenguaje natural.

**Por qué te importa:** Si construyes automaciones con n8n que necesitan interactuar con UIs sin API, esto elimina la dependencia de Playwright/Puppeteer para casos simples. También relevante para flujos de scraping o testing de interfaces. Está en trending de GitHub esta semana (top 3 junto con openai/codex-plugin-cc).

**Acción sugerida:** Explorar — evalúa si el modelo de inyección JS encaja con tus casos de uso de automatización web.

### Microsoft Agent Framework 1.0 — AutoGen + Semantic Kernel unificados (MIT)

Microsoft fusionó AutoGen y Semantic Kernel en [Microsoft Agent Framework 1.0](https://learn.microsoft.com/en-us/agent-framework/overview/) (lanzado el 3 de abril, MIT license, .NET y Python). Combina las abstracciones de agentes de AutoGen con las funcionalidades enterprise de Semantic Kernel: estado de sesión, type safety, middleware, telemetría, y workflows basados en grafos.

**Por qué te importa:** Si tienes proyectos con AutoGen o Semantic Kernel, Microsoft tiene guías de migración activas. Si usas LangGraph o CrewAI directamente, el impacto es bajo hoy — pero si un cliente pide integración con Azure Foundry Agent Service, este es el SDK que debes conocer. Para arquitecturas pure-Python sin Azure, LangGraph 1.0 sigue siendo mejor opción para workflows stateful complejos.

**Acción sugerida:** Monitor — revisar en profundidad cuando toque un proyecto Azure-heavy.
