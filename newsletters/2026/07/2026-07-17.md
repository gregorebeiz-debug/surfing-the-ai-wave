### Claude Sonnet 5: El Sonnet más capaz hasta la fecha

Lanzado el 30 de junio, Claude Sonnet 5 está siendo el modelo de facto para agentes en producción esta semana. Capacidades cercanas a Opus en coding (especialmente en brownfield code con race conditions), razonamiento extendido activado por defecto (adaptive thinking on), y ventana de 1M tokens. El precio de introducción ($2/M input, $10/M output hasta agosto 31) lo hace sustancialmente más económico para pipelines agenticos de alto volumen. El model ID es `claude-sonnet-5`.

**Importante antes de migrar:** El tokenizer nuevo genera ~30% más tokens por el mismo texto. Si tienes agentes en producción con presupuesto de tokens ajustado, recalcula antes de cambiar el model ID. Extended thinking manual ahora devuelve 400 — todo es adaptive por defecto.

### GPT-5.6 + ChatGPT Work: OpenAI lanza su apuesta agentica más ambiciosa

El 9 de julio OpenAI abrió GPT-5.6 al público en tres tiers: **Sol** (flagship, state-of-the-art en coding/cybersecurity/ciencia), **Terra** (balanceado para uso cotidiano), **Luna** (velocidad). La jugada real es **ChatGPT Work**: un agente que ejecuta tareas completas durante horas, conecta tus apps, genera sheets/slides/docs/web apps, y usa un browser integrado. Multi-agent (subagentes concurrentes) entra en beta. Cache explícita con breakpoints definibles y vida mínima de 30 min.

**El contexto crítico:** ChatGPT Work apunta directamente al espacio de los workflow builders individuales. La diferencia que sigue importando: control del pipeline, privacidad de datos, customización de lógica de orchestration. Prepárate para el argumento de clientes de "ya para qué automation custom si tengo ChatGPT Work".

*Fuentes: [Axios](https://www.axios.com/2026/07/09/ai-openai-gpt-release), [TechCrunch](https://techcrunch.com/2026/07/09/openai-launches-its-new-family-of-models-with-gpt-5-6/), [OpenAI](https://openai.com/index/gpt-5-6/)*

## 🔧 Tool & Repo Watch — Herramientas y repos

### MCP 2026-07-28 Spec — Release Candidate: El protocolo se rehace
**Qué es:** La revisión más grande del Model Context Protocol desde su lanzamiento entra en RC hoy. Spec definitivo: julio 28, 2026.

**Cambios que te afectan directamente:**
- **Sin sesiones:** Elimina `Mcp-Session-Id` — un servidor MCP remoto ahora puede correr detrás de un load balancer estándar sin sticky sessions ni session store compartido. Deployar un MCP server propio se simplifica enormemente.
- **Sin handshake:** Client capabilities viajan en `_meta` en cada request. Nuevo método `server/discover` reemplaza el handshake inicial.
- **MCP Apps:** Servidores pueden incluir interfaces HTML en iframes sandboxeados — UI nativa dentro del host (Claude, VS Code, Claude Code).
- **Tasks extension:** Llamas a una tool, el servidor devuelve un task handle, el cliente trackea con `tasks/get`, `tasks/update`, `tasks/cancel`. Diseñado para operaciones largas sin timeout.
- **Auth OAuth 2.1/OIDC:** Enterprise-grade nativo, alineado con estándares existentes.

**Por qué te importa:** Todo MCP server que construyas a partir del 28 de julio debería apuntar a este spec. Servers stateless son más simples de deployar y escalar. Si tienes MCP servers custom en producción, tienes mínimo 12 meses de período de deprecación — empieza a planear la migración, no hay urgencia inmediata.

→ [Spec RC blog](https://blog.modelcontextprotocol.io/posts/2026-07-28-release-candidate/) | [Qué cambia en detalle](https://stacktr.ee/blog/mcp-2026-spec-changes) | Acción: **Monitor / Planear migración**

### n8n AI Assistant — El agente que construye tus workflows desde adentro
**Qué es:** Agente de chat integrado directamente en n8n que construye, edita, testea y troubleshootea workflows en lenguaje natural.

**Por qué te importa:** Hasta ahora armar un workflow en n8n requería drag-and-drop manual o conocer los nodos de memoria. ### LangGraph — Per-node timeouts, DeltaChannel y v2 Streaming API
**Qué es:** LangGraph agregó per-node timeouts, DeltaChannel, y una v2 typed streaming API. Superó a CrewAI en GitHub stars en 2026 por adopción enterprise.

**Por qué te importa:** Per-node timeouts son críticos para agentes en producción — evitan que un nodo colgado tumbe todo el grafo. Si construyes pipelines multi-step donde algún nodo llama APIs externas o LLMs con latencia variable, esto va directo a resiliencia. La v2 streaming API simplifica consumo de streams en frontends (Next.js, etc.). Si tienes código LangGraph existente, revisa breaking changes antes de actualizar.

→ [LangChain resources](https://www.langchain.com/resources/ai-agent-frameworks) | Acción: **Actualizar si usas LangGraph en producción**

## ⚠️ Buyer Beware — Alerta de hype

**Todos hablan de ChatGPT Work como "el fin de los workflow builders".**

ChatGPT Work es un agente centralizado dentro del ecosistema OpenAI — sin acceso a sistemas on-premise, sin control sobre el pipeline de datos, sin posibilidad de customizar la lógica de orchestration, sin integración con herramientas propias más allá de las que OpenAI apruebe. Los workflows que construyes en n8n + Claude Code son propios, auditables, extensibles, y pueden conectarse a cualquier sistema. ChatGPT Work resuelve el caso de uso del knowledge worker individual que quiere delegar tareas de oficina. No resuelve el caso del builder que construye sistemas para terceros o pipelines con requisitos de privacidad/customización. El riesgo real no es reemplazamiento técnico — es que stakeholders o clientes lo vean como sustituto y cuestionen el valor de automation custom. Prepárate para ese argumento con ejemplos concretos de lo que tu stack hace que ChatGPT Work no puede.
