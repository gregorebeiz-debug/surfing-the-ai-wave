## 🌊 The Wave Today — Noticias que mueven la aguja

### OpenAI lanza GPT-5.6: familia Sol / Terra / Luna

El 9 de julio, OpenAI liberó públicamente GPT-5.6 después de semanas de retraso por solicitud del gobierno de EE.UU. (concerns de seguridad nacional). Son tres modelos en una familia:

- **Sol** (flagship): $5 input / $30 output por 1M tokens — razonamiento frontier y trabajo agéntico de largo alcance. Altman afirma 54% más eficiente en tokens para coding. Corre en Cerebras a hasta 750 tokens/seg.
- **Terra** (mid-tier): $2.50 / $15 por 1M — performance GPT-5.5-competitive a 2x menor costo.
- **Luna** (fast): $1 / $6 por 1M — el más rápido y económico.

Los tres: 1M tokens de contexto, 128K tokens de output máximo, knowledge cutoff febrero 2026, caching explícito con cache breakpoints y vida mínima de 30 minutos. OpenAI también lanzó **ChatGPT Work**, asistente de equipo que integra contexto de herramientas existentes.

La jugada estratégica no es el benchmark (53.6 en Agents' Last Exam — ver Buyer Beware). Es la combinación de precio + velocidad: Sol en Cerebras a 750 tok/seg es una propuesta diferente a todo lo anterior en el tier frontier.

### Claude Cowork llega al cloud — tareas agénticas sin laptop abierta

El 7 de julio, Anthropic movió Cowork a la nube. Las sesiones ya no viven en tu máquina; viven en servidores de Anthropic. Lo que cambia en práctica:

- **Laptop cerrada ≠ tarea cancelada**: el trabajo agéntico continúa en background cloud
- **Cross-device real**: empezás en desktop, seguís en móvil, cerrás en web — sesiones y archivos te siguen
- **Scheduling sin dispositivo activo**: tareas programadas corren aunque no haya ningún dispositivo online

Acceso beta primero para Max subscribers; límites de uso duplicados hasta el 5 de agosto. La app de desktop sigue siendo necesaria para flujos que dependen de archivos locales o conectores instalados localmente.

Contexto crítico: esto cierra la brecha que tenía Cowork vs. herramientas como n8n cloud. Antes, si cerrabas el laptop, el agente paraba. Ahora no. El movimiento apunta directo al mercado de agentes de automatización de oficina.

### Claude Sonnet 5 es el nuevo default desde el 1 de julio

Importante si aún no ajustaste tus agentes: Sonnet 5 (lanzado el 30 de junio) es ahora el modelo por defecto para usuarios Free y Pro. Lo que cambia:

- Performance cerca de Opus 4.8 en muchas tareas
- $2 / $10 por 1M tokens — precio introductorio válido **hasta el 31 de agosto**
- El Sonnet más agéntico hasta la fecha: mejor planning, uso autónomo de browser y terminal, tareas multi-step sin intervención constante
- Primer Sonnet con real-time cybersecurity safeguards

Si tus pipelines en Claude Code o Claude Agent SDK están anclados a `claude-sonnet-4-6`, hay una ventana de precio favorable para migrar antes de que venza el introductorio.

## 🔧 Tool & Repo Watch — Herramientas y repos

### MCP 2026-07-28 Spec: Release Candidate activo — 15 días

**Qué es:** La mayor revisión del protocolo MCP desde su lanzamiento. El RC está disponible hoy; la spec final sale el 28 de julio.

**Los cambios que te afectan:**

- **Stateless core**: el transporte Streamable HTTP ahora requiere headers `Mcp-Method` y `Mcp-Name`. Un MCP server que antes necesitaba sticky sessions puede ahora correr detrás de un load balancer round-robin sin inspección de paquetes.
- **Caching explícito** (`ttlMs` + `cacheScope` en responses de `tools/list`): los clientes saben exactamente cuánto tiempo un resultado es válido.
- **MCP Apps** (extensión nueva): los servers pueden enviar UIs HTML que el host renderiza en iframe sandboxed.
- **Tasks extension**: work de larga duración como ciudadano de primera clase en el protocolo.

**Por qué te importa:** Usás Claude Code con MCP servers a diario. Si tenés MCP servers propios en construcción o producción, este spec cambia los requisitos de headers. Los SDK Tier 1 tienen 10 semanas para implementar soporte — pero el RC ya está disponible para probar.

**Acción sugerida:** Explorar. Leer el RC en [blog.modelcontextprotocol.io](https://blog.modelcontextprotocol.io/posts/2026-07-28-release-candidate/). Auditar tus MCP servers contra el nuevo spec de headers antes del 28.

### Claude Code: browser integrado + /doctor que arregla (no solo reporta)

**Dos updates concretos llegaron esta semana:**

1. **Built-in browser sandboxed**: Claude Code en desktop ahora puede navegar docs, diseños y sitios externos — leer, clickear, interactuar. Configurable: elegís si las sesiones persisten. Clasificadores de seguridad revisan acciones en sitios externos. Esto elimina el loop de "Claude pide URL → vos buscás → pegás resultado → Claude procesa" y lo reemplaza por navegación directa dentro del agente.

2. **/doctor ahora repara**: el comando mejorado puede diagnosticar Y arreglar. Encuentra MCP servers y skills sin usar, deduplica archivos CLAUDE.md locales vs. los del repo, propone recortes de contenido, y ahora ejecuta los fixes — no solo los lista.

**Correcciones MCP también incluidas:** fixed timeout de 60s que ignoraba configuración per-server; fixed OAuth que pedía re-auth tras un token refresh fallido.

**Por qué te importa:** El browser integrado es el cambio más estructural — convierte Claude Code en un agente que puede ir a buscar información activamente mientras trabaja en tu código. El /doctor mejorado es utilidad directa: correlo para auditar tu setup y limpiar lo que no usás.

**Acción sugerida:** Instalar. Actualizar Claude Code a la última versión. Correr `/doctor` en tu entorno actual.

### n8n AI Assistant — Workflows en lenguaje natural, desde adentro de n8n

**Qué es:** n8n lanzó su AI Assistant en Preview (n8n cloud, desde v2.29.9): un agente de chat integrado en la UI de n8n que crea, edita, testea y debuggea workflows desde lenguaje natural. Describís qué querés automatizar → el asistente construye el workflow, lo testea, y te ayuda a corregir errores.

**Por qué te importa:** Usás n8n para automatización. Esto cambia el flujo de construcción de manera fundamental: en lugar de arrastrar y configurar nodos manualmente, el asistente lo hace por vos. Para workflows complejos con muchos nodos o integraciones nuevas, el tiempo de construcción se puede reducir significativamente.

**Limitación honesta:** Preview. Los LLMs que construyen workflows cometen errores en lógica compleja con muchas condiciones o edge cases — requiere revisión humana por ahora.

**Acción sugerida:** Explorar si estás en n8n cloud.

## ⚠️ Buyer Beware — Alerta de hype

**GPT-5.6 Sol: 53.6 en Agents' Last Exam no es lo que parece**

Todos los outlets están citando el número: 53.6 en Agents' Last Exam, +13.1 puntos sobre Claude Fable 5 (adaptive reasoning). Suena definitivo. No lo es todavía.

Tres razones para no migrar pipelines de producción esta semana:

1. El benchmark fue construido sobre 55 campos evaluados — un eval creado **después** de que existían los modelos que compite. Historia larga de overfitting a evals propios en la industria.
2. El claim de "+54% de eficiencia en tokens para coding" viene de Altman en una entrevista de CNBC. Sin metodología publicada al cierre de esta edición.
3. El rollout inicial fue a ~20 organizaciones pre-aprobadas por el gobierno — muestra pequeña para sacar conclusiones de producción.

GPT-5.6 Sol muy probablemente es un modelo capaz. Pero "nuevo record el día del lanzamiento" tiene una tasa histórica de overpromise alta en el sector LLM. Esperá evaluaciones independientes (Artificial Analysis, LMSYS, evals de usuarios reales) antes de mover workloads críticos.
