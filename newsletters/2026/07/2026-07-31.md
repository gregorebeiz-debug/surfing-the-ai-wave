### MCP 2026-07-28: El protocolo se reinventa — stateless, extensible, enterprise-ready

El Model Context Protocol publicó su spec más grande desde el lanzamiento. El cambio central: MCP pasa de protocolo bidireccional con estado a un modelo request/response stateless. En términos prácticos, los servidores MCP ahora pueden vivir en infraestructura serverless y edge — sin SSE, sin sesiones persistentes, sin el overhead de mantener conexiones abiertas.

Cambios que impactan directamente tu stack:
- **Roots, Sampling y Logging están deprecados** (siguen funcionando 12 meses, pero empieza a planear la migración)
- **Tasks** sale del core y entra como extensión `io.modelcontextprotocol/tasks` con poll-based `tasks/get` y `tasks/update`
- **MCP Apps**: UIs server-rendered en iframes sandboxed — tus servidores MCP ahora pueden tener UI propia
- **Enterprise Managed Auth**: conecta MCP a tu identity provider (OAuth/OIDC) — control centralizado de acceso
- **MCP Tunnels** (research preview): conecta Claude a servidores en redes privadas sin exponer endpoints públicos ni configurar reglas de firewall

Claude ya soporta el nuevo spec. Si tienes servidores MCP propios, revisa breaking changes en el changelog oficial antes del deadline de soporte legacy.

### GPT-5.6 + ChatGPT Work: OpenAI apunta directo a los agentes de trabajo

El 9 de julio OpenAI lanzó GPT-5.6 en tres tiers (Luna/Terra/Sol) junto con ChatGPT Work — su respuesta directa al espacio de agentes autónomos. ChatGPT Work no es un chatbot mejorado: toma un objetivo, conecta con tus apps, descompone el trabajo en pasos, y los ejecuta solo — entregando spreadsheets, slides, documentos y web apps terminados. Incluye Plan Mode (apruebas el plan antes de que ejecute) y action approvals para controlar el nivel de autonomía.

Datos técnicos: 1.5M token context en Enterprise (3.75x GPT-5.5), tasa de rechazo de tool-calls bajó de ~12% a <4% en benchmarks de agentes. También lanzó GPT-Live-1 para voz más natural y ChatGPT for Academic Researchers con acceso gratuito a 10,000 investigadores (escalando a 100,000 en 2027).

Contexto: esto compite directamente con Claude Code en el espacio de "agentes que completan trabajo real". La diferencia de velocidad entre releases ahora se mide en semanas.

## 🔧 Tool & Repo Watch — Herramientas y repos

### n8n Instance-Level MCP Server (v2.18.4+, Public Preview)
n8n ahora actúa simultáneamente como MCP Client y MCP Server. La función más útil: exponer cualquier workflow de n8n como una "herramienta" para Claude Desktop, ChatGPT, Cursor, o cualquier cliente MCP-compatible — sin código adicional. Como MCP Client, los agentes de n8n pueden descubrir y usar herramientas externas MCP-compatibles sin wrappers de API customizados.

**Por qué te importa:** Si ya tienes workflows de n8n construidos (automatizaciones de negocio, pipelines de datos, integraciones con APIs), ahora Claude Code puede llamarlos directamente como herramientas. La distancia entre "tengo un workflow" y "mi agente usa ese workflow" es cero. Conexiones simplificadas disponibles desde el panel: Apify, Linear, monday.com, Notion, PostHog.

→ [Docs n8n](https://docs.n8n.io/changelog/release-notes-2.x) | Acción: **Actualizar** si usas Community Edition (v2.18.4+), habilitar en Cloud si ya tienes workflows relevantes [AI Automation]

### Inkling — 975B Open-Weight, Apache 2.0 (Thinking Machines Lab / Mira Murati)
La ex-CTO de OpenAI lanzó el 15 de julio su primer modelo: mixture-of-experts de 975B parámetros totales / 41B activos, 1M token context, Apache 2.0 puro, entrenado en 45T tokens multimodales (texto, imagen, audio, video).

**Por qué te importa:** Apache 2.0 significa sin restricciones comerciales. Con 41B parámetros activos (no 975B), la inferencia es viable con hardware serio. Si necesitas un modelo self-hosted para workflows que no pueden salir de tu infraestructura — datos sensibles de clientes, pipelines sin dependencia de APIs externas — Inkling es la primera opción en esta categoría que combina escala real, apertura y licencia limpia.

### Mori + Memoir + Memvid — Memory Systems para Agentes de Coding
Tres proyectos de memoria específicos para agentes aparecieron en el radar de julio 2026:
- **Mori**: Capa de memoria compartida soberana para agentes de coding — múltiples agentes leen/escriben el mismo contexto
- **Memoir**: Memoria semántica versionada estilo git — puedes hacer diff y rollback de lo que el agente "sabe"
- **Memvid**: Capa de memoria single-file sin servidor — serverless, portátil

**Por qué te importa:** Si tu frustración con Claude Code es que pierde contexto entre sesiones más allá de CLAUDE.md, estos proyectos atacan exactamente eso. Memoir en particular (git-versioned semantic memory) mapea bien a un workflow donde múltiples agentes necesitan compartir y auditar contexto de proyecto. Mori complementa el modelo de multi-agent que ya viene en Claude Code.
