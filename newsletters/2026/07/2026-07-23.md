### OpenAI lanza GPT-5.6 (Sol/Terra/Luna) + ChatGPT Work

El 9 de julio, OpenAI lanzó **GPT-5.6** en tres niveles: **Sol** (flagship, mejor modelo de codegen y ciberseguridad), **Terra** (balance rendimiento/costo para trabajo diario) y **Luna** (rápido y barato para volumen). Pero lo que realmente cambia el juego es **ChatGPT Work**: un agente integrado directamente en ChatGPT que no devuelve respuestas — entrega entregables terminados. Hojas de cálculo, slides, reportes, web apps. Se conecta con tus apps vía un directorio de plugins y puede ejecutar tareas en horario programado, corriendo en segundo plano durante horas con Codex integrado.

**Análisis crítico:** El posicionamiento de Sol como "modelo de ciberseguridad más potente de OpenAI" (threat modeling, code review, patching) es audaz y verificable — o no. Esos claims requieren escrutinio real, no benchmarks propios. ChatGPT Work compite directamente con Claude Code en modo agéntico y con n8n/Make para automatización; si OpenAI conecta bien los plugins empresariales, la fricción de adopción desaparece para equipos que ya viven en Microsoft 365. Desde el 22 de julio, GPT-5.6 Sol es el modelo por defecto en **Microsoft 365 Copilot** — cambio silencioso bajo miles de usuarios corporativos.

### Kimi K3 — China cierra la brecha con 2.8 billones de parámetros

Moonshot AI lanzó **Kimi K3** el 16 de julio: el mayor modelo open-weight de la historia con **2.8 billones de parámetros**. Los benchmarks son serios y no autopublicados: **93.5% GPQA Diamond** (el mejor resultado open-weight publicado), **91.2% BrowseComp**, **88.3% Terminal-Bench 2.1**. En el ranking independiente GDPval-AA v2, K3 quedó tercero global — detrás únicamente de Claude Fable 5 Max y GPT-5.6 Sol Max.

El dato que más duele: **venció a Claude Fable 5 en el Frontend Code Arena** (evaluación ciega por desarrolladores reales). Los pesos públicos llegan el **27 de julio** — si estás interesado en explorar el modelo open-weight más capaz que existe para coding y agentes, esa es la fecha a marcar. Y esto ocurre mientras China sigue operando bajo restricciones de cómputo de EE.UU., lo cual hace el resultado aún más significativo como señal de tendencia.

### Claude Code v2.1.218 — Fix crítico para sesiones largas y worktrees

Claude Code publicó ayer (22 de julio) la versión **v2.1.218**, con dos correcciones de alto impacto para usuarios de Auto mode y flujos multi-agente:

1. **Quadratic slowdown eliminado:** En sesiones largas de Auto mode, la latencia acumulaba de forma cuadrática — cuanto más corría la sesión, exponencialmente más lento se ponía. El fix aplica directamente en sesiones de trabajo pesado donde dejas Claude Code corriendo durante horas.
2. **Worktree isolation hardening:** Subagentes corriendo en worktrees aislados podían escapar el sandbox y redirigir operaciones git al checkout principal via `--git-dir`, `GIT_DIR`, `GIT_WORK_TREE`, o `git -C`. El isolation boundary ahora cierra esos vectores.

Si usas Claude Code con background agents, workflows de subagentes, o sesiones de Auto mode que duran horas — **actualiza ahora**.

*Fuentes: [Tech Times](https://www.techtimes.com/articles/321326/20260723/claude-code-update-kills-quadratic-slowdown-that-compounded-auto-modes-longest-sessions.htm), [Releasebot](https://releasebot.io/updates/anthropic/claude-code)*

## 🔧 Tool & Repo Watch — Herramientas y repos

### Hallmark — Skill de diseño anti-slop para Claude Code

Un skill para Claude Code (compatible con Cursor y Codex) que ejecuta **57 "slop-test" gates** más una auto-crítica pre-emisión antes de devolver cualquier interfaz de usuario. El objetivo: que los componentes y layouts generados por IA se sientan deliberados e intencionales, no genéricos.

**Por qué te importa:** Si usas Claude Code para generar UI — componentes React, layouts Next.js, diseños v0 — este skill ataca el problema más visible del vibe-coding: interfaces que funcionan pero que visualmente gritan que las hizo una IA. Integrarlo como skill en tu configuración de Claude Code es trivial una vez que entiendes el sistema de skills. El número de gates (57) sugiere que es exhaustivo, no decorativo.

→ **Acción sugerida:** Instalar / Explorar. [GitHub Trending](https://www.analyticsvidhya.com/blog/2026/07/trending-ai-github-repositories/) [Claude Ecosystem]

### OpenWiki — Documentación AI-friendly automática para tu codebase

CLI del equipo de LangChain que **genera y mantiene automáticamente documentación estructurada para agentes IA** sobre tu codebase. Diseñado para que agentes de coding puedan navegar proyectos complejos sin desperdiciar tokens explorando estructura.

**Por qué te importa:** Si tienes subagentes de Claude Code trabajando en repos medianos o grandes, el overhead de "entender dónde está cada cosa" es real y costoso en tokens. OpenWiki genera el mapa que el agente necesita upfront. Complementa bien la arquitectura de worktrees que ya usa Claude Code — el agente sabe la estructura, el worktree lo aisla.

→ **Acción sugerida:** Explorar — potencial alto para proyectos multi-módulo. [GitHub Trending](https://www.analyticsvidhya.com/blog/2026/07/trending-ai-github-repositories/) [Agentic Infrastructure]

### CrewAI v1.14 — Backends de memoria y RAG intercambiables

**CrewAI 1.14** introduce backends pluggables de memory/knowledge/RAG: ahora conectas tu propio vector store o sistema RAG en lugar de depender del default.

**Por qué te importa:** Si construyes agentes CrewAI con necesidad de memoria persistente o acceso a bases de conocimiento propias (catálogos, docs de cliente, knowledge bases de negocio), esta versión convierte eso en configuración, no en código custom.
