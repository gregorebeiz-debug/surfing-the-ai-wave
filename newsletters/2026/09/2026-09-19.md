## 🌊 The Wave Today — Noticias que mueven la aguja

### Claude dirige el 26% de su propio I+D — y la curva es vertical

Anthropic publicó ayer una de las métricas más significativas del año: Claude ya lidera de forma autónoma el 26% de toda la investigación y desarrollo de los modelos Anthropic. "Liderar" significa trabajo completo end-to-end desde un prompt de alto nivel, bajo supervisión humana pero sin dirección granular. El dato más impactante: en febrero este porcentaje era **cero**. Seis meses para llegar a un cuarto del I+D de un laboratorio frontier.

El 90% restante del trabajo de I+D es "colaboración cercana" donde Claude hace grandes bloques bajo dirección humana activa. Anthropic eligió publicar estas métricas precisamente porque la aceleración del recursive self-improvement podría "dificultar el control humano" — y quieren que el mundo entienda qué tan rápido se mueve la curva.

Esto no es hype de marketing. Son métricas operacionales internas. El salto de 0% a 26% en seis meses, si continúa a este ritmo, lleva a números muy incómodos para finales de 2027.

### GPT-6 Astra: Los benchmarks que cambian la conversación competitiva

OpenAI lanzó GPT-6 Astra el 3 de septiembre con el entrenamiento más grande de su historia (100,000+ GPUs, Stargate Texas, y por primera vez modelos anteriores supervisando el entrenamiento del nuevo). Los números de benchmark son difíciles de ignorar: 97.6% en FrontierMath Tier 4, 99.9% en ARC-AGI-3, 100% en ExploitBench. En computer use (OSWorld 2.0), Astra logra 72.6% en ~40 minutos, comparado con GPT-5.6 Sol haciendo 65.7% en ~75 minutos.

La métrica que realmente presiona a Anthropic: Astra empata con Claude Fable 5.1 en el Intelligence Index **a ~40% del costo**. En el Coding Agent Index, mismo empate a ~60% del costo de Fable. El pricing de Astra es $10/$50 por millón de tokens (input/output), 2.5x GPT-5.6 Sol — caro para uso masivo, pero la ecuación precio/capacidad es competitiva.

Señal de alarma que merece atención separada: durante la evaluación de ciberseguridad, Astra descubrió y utilizó **dos vulnerabilidades zero-day previamente desconocidas**. OpenAI las está revelando a los mantenedores. Primera vez que un modelo de producción descubre CVEs reales en evaluación controlada. Esto tiene implicaciones para cómo pensamos en despliegue de modelos muy capaces.

### OpenAI convierte ChatGPT en plataforma publicitaria con agentes de marca

El 16 de septiembre OpenAI formalizó "Sponsored Agents": cuando un usuario toca un anuncio en ChatGPT, no lo manda a un sitio web externo — lo conecta directamente con un agente IA del anunciante dentro de la misma conversación. Wayfair, Angi, Newegg, Best Buy, Lowe's y VistaPrint están en el piloto inicial. La división publicitaria de OpenAI ya superó $1B ARR en menos de 200 días.

El modelo es elegante en su lógica: el agente te ayuda genuinamente primero, luego te vende cuando estás listo. Está claramente etiquetado como agente patrocinado. El problema real es estructural: el incentivo del agente ya no es solo ser útil — es ser útil de forma que maximice conversión para el anunciante.

Para quien trabaja en ecommerce + AI: el canal de adquisición está cambiando. El customer journey pasa cada vez más por conversaciones con agentes.

*Fuentes: [Forkast News](https://forkast.news/openais-sponsored-agents-turn-chatgpt-into-an-ad-platform-where-brands-are-the-product/), [AI Weekly](https://aiweekly.co/alerts/openai-pilots-sponsored-agents-in-chatgpt-with-wayfair-angi), [OpenAI](https://openai.com/index/reimagining-advertising-with-ai/)*

## 🛠️ Tool & Repo Watch — Herramientas y repos

### Claude Code Plugin Eval — Testing reproducible para skills y plugins

**Lanzado:** v2.1.269, 11 de septiembre de 2026

`claude plugin eval` corre tu plugin contra una suite de test cases, mide el delta vs. un baseline sin plugin, y produce resultados en JSON y HTML para CI. Cada caso corre 3 veces con el plugin y 3 veces sin él — el Δ muestra exactamente qué aporta el plugin. El sistema incluye 6 tipos de graders. `claude plugin eval init` hace bootstrapping: te pregunta qué es un buen resultado, propone test cases y los graders, y escribe los archivos.

**Por qué te importa:** Construyes skills y usas plugins en Claude Code a diario. Hasta ahora testear un plugin era subjetivo — "parece que funciona". Ahora tienes testing estadístico reproducible con CI gate. Esto es para ti: si tienes skills activos en tu setup de Claude Code, `claude plugin eval init` en cada uno te da visibilidad que antes no existía. También es clave si estás pensando publicar o vender plugins.

**Acción sugerida:** Instalar / Usar — correr `claude plugin eval init` en tu setup actual.

### fast-jev-compaction — Compaction sin pérdida de contexto para Claude Code

**GitHub:** ~3,500 estrellas (múltiples forks activos) | TypeScript/npm

Reemplaza el resumen de compactación de Claude Code por decisiones de Jev: cada tool call y resultado se scorea en una sola request rápida, los que ya no son relevantes se eliminan o truncan, y todo lo conservado queda **verbatim** — sin reescritura, sin pérdida de paths exactos, errores específicos o constraints críticos.

El problema que resuelve: la compactación estándar de Claude Code es lossy — puede eliminar un path exacto, un mensaje de error específico, o una constraint de arquitectura que definiste al inicio de la sesión. Este plugin nunca reescribe nada, solo decide qué cortar mostrando la conversación completa a Jev mientras toma esa decisión.

**Por qué te importa:** Trabajas en repos grandes y tareas multi-step con Claude Code. Las sesiones largas donde Claude Code "olvida" algo que definiste al principio son frustración directa. Este plugin ataca exactamente ese problema. Disponible como npm package y como Claude Code plugin listo para instalar.

**Acción sugerida:** Explorar / Instalar.

→ [GitHub](https://github.com/alepee/fast-jev-compaction)

### n8n v2.36 — AI providers integrados sin cuentas externas

**Disponible en:** n8n Cloud (planes seleccionados)

Relevante especialmente para prototipar antes de decidir qué provider usar en producción. Aplica solo a planes n8n Cloud — verifica cuál tienes.

### MCP Spec 2026-07-28 — Protocolo stateless, Multi Round-Trip Requests, MCP Apps

El spec oficial de MCP publicado en julio trajo el cambio más solicitado por developers: **protocolo stateless** (de bidireccional stateful a request/response). También: Multi Round-Trip Requests para operaciones complejas, header-based routing, cacheable list results, authorization hardening, y un extensions framework formal. Destacado: **MCP Apps** — UI elements interactivos renderizables inline dentro de conversaciones.

**Por qué te importa:** Si construyes o planeas construir MCP servers (tu stack prioritario #1), este spec es el estándar vigente desde julio. El cambio a stateless resuelve problemas reales de confiabilidad y escalabilidad que tenían los servidores anteriores. MCP Apps abre la puerta a agentes con UI rica dentro de Claude. Revisa si tus MCP servers actuales son compatibles.

**Acción sugerida:** Explorar / Actualizar servidores MCP existentes.

→ [Spec oficial](https://modelcontextprotocol.io/specification/2026-07-28) | [Blog MCP roadmap](https://blog.modelcontextprotocol.io/posts/2026-07-28/)
