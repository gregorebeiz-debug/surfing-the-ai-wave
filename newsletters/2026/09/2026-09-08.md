### Anthropic lanza Fable 5.1 y Mythos 5.1: el precio real no es lo que parece

El 1 de septiembre, Anthropic hizo available en general Claude Fable 5.1 (acceso abierto) y Mythos 5.1 (acceso restringido, trusted-access). El titular fue **75% de reducción en cache reads**: de $1.00 a $0.25 por millón de tokens. El precio base se mantiene en $10 input / $50 output — igual que Fable 5.

El impacto neto en workflows agentic cache-heavy es de hasta 45% de ahorro. Pero hay una letra pequeña crítica: **testing independiente de Artificial Analysis encontró que Fable 5.1 usa ~1.7x más output tokens para resolver el mismo task** que su predecesor. En workloads sin mucho caching, el costo total por task puede ser más alto, no más bajo.

Lo que importa para agentes: si tu pipeline cachea heavily (repetición de contexto, system prompts largos, RAG con docs estáticos), el ahorro es real. Si es output-heavy (generación larga, código extenso), evalúa antes de migrar.

Specs técnicas: `claude-fable-5-1`, contexto de 1M tokens, 128K max output, adaptive thinking siempre activo, knowledge cutoff junio 2026.

### Claude Code 2.1.261: MCP para organizaciones, sessions concurrentes y diff panel

En la misma semana, Claude Code acumuló updates significativos hasta la versión 2.1.261:

- **managedMcpServers** — nueva setting organizacional que permite proveer HTTP/SSE MCP servers a todos los usuarios de una org sin que cada uno configure su `.mcp.json`. Para equipos que despliegan servers internos de MCP, esto es un game changer de onboarding.
- **`--permission-prompts none`** — nuevo flag para headless/unattended execution: todo lo que requeriría un prompt se deniega automáticamente. Ideal para CI, automation sin supervisión.
- **Fix de sessions concurrentes** — bug crítico resuelto: múltiples sesiones ya no revierten silenciosamente cambios de `~/.claude.json`, ni resetean workspace trust ni pierden estado de MCP/proyectos.
- **Side-by-side diff panel** — revisión de cambios en tiempo real mientras Claude edita. Reduce sorpresas en edits largos.
- Claude Code ahora defaultea a **Fable 5.1 como modelo base** desde la versión 2.1.257.

*Fuentes: [Claude Code Changelog](https://code.claude.com/docs/en/changelog), [Releasebot](https://releasebot.io/updates/anthropic/claude-code), [Havoptic](https://www.havoptic.com/tools/claude-code)*

### OpenAI lanza GPT-6 Astra — y los benchmarks merecen escepticismo

El 3 de septiembre, OpenAI lanzó GPT-6 Astra al mismo precio que Fable 5.1: $10/$50 por millón de tokens. Los números son llamativos:

- 72.6% en OSWorld 2.0 (computer use) — mejor que GPT-5.6 Sol (65.7%)
- "100%" en ExploitBench (vulnerabilidades a exploits funcionales)
- 99.9% en ARC-AGI 3

El problema: **los benchmarks de Astra están medidos con el "Provider Adapter harness" propio de OpenAI**, no con los harnesses estándar. ARC-AGI 3 en el harness por defecto da 62.7% — un número muy diferente. ExploitBench al 100% también usa setup personalizado.

Dicho esto, el 72.6% en computer use es comparable con hardware estándar, y la reducción de 47% en tiempo por task (40 min vs 75 min de Sol) sí parece real. Para comparación: Fable 5.1 queda en 70% en ExploitBench.

Astra es el primer modelo que activó el umbral de "critical-cyber safeguard" de OpenAI — datos de capacidades de ciberseguridad que la empresa toma seriamente en su safety framework.

*Fuentes: [DataNorth](https://datanorth.ai/news/openai-launches-gpt-6-astra), [Vellum](https://www.vellum.ai/blog/gpt-6-astra-benchmarks-explained), [Simon Willison](https://simonwillison.net/2026/Sep/3/gpt6-astra/)*

## 🔧 Tool & Repo Watch — Herramientas y repos

### n8n — MCP nativo en producción

**Qué hay nuevo:** n8n agregó soporte nativo para Model Context Protocol (MCP) como integration layer, y habilitó Task Runners por defecto en todos los Code nodes — cada ejecución corre en proceso aislado para evitar crashes por loops infinitos.

**Por qué te importa:** Si usas n8n para orquestar workflows con AI, MCP nativo significa que puedes conectar directamente tus Claude MCP servers dentro de los flows sin workarounds intermedios. Y el aislamiento de procesos era el pain point más común con el Code node — este fix es largo tiempo esperado.

**Acción sugerida:** Actualiza y revisa tus flows con Code nodes — el comportamiento de aislamiento puede romper patterns que dependían de estado compartido entre ejecuciones.

*Fuente: [n8n Blog](https://blog.n8n.io/), [CipherNutz](https://ciphernutz.com/blog/n8n-workflow-automation-latest-features)*

### CrewAI — A2A enterprise-grade

**Qué hay nuevo:** CrewAI reporta que su integración Agent-to-Agent (A2A) está ahora en production-ready para enterprise — múltiples agentes comunicándose entre sí en escenarios de alta carga.

**Por qué te importa:** Si estás evaluando CrewAI vs LangGraph para multi-agent production: benchmarks recientes (abril 2026, tasks de 8+ pasos) dan LangGraph 62% completion vs CrewAI 54%. LangGraph también cuesta menos por run. CrewAI tiene mejor DX y más features out-of-the-box. Para proyectos serios de autonomía real, LangGraph sigue siendo el más sólido técnicamente.

**Acción sugerida:** Si ya usas CrewAI con comunicación inter-agente, el update de A2A es relevante. Si estás empezando, evalúa LangGraph para workflows críticos.

*Fuente: [DutchStartup.ai](https://www.dutchstartup.ai/en/news/a-wave-of-new-ai-agent-tools-is-emerging-around-early-september-2026)*

### magnitudedev/magnitude — Inference router para local models

**Qué es:** Servidor de inferencia open source que enruta modelos locales al frontend de agentes que ya uses — compatible con múltiples agent frontends sin reconfiguración.

**Por qué te importa:** Si trabajas con modelos locales (Ollama, etc.) y quieres conectarlos a pipelines de agentes existentes sin reescribir la integración, magnitude hace ese routing transparente. Reduce el lock-in a inference providers.

**Acción sugerida:** Explorar — especialmente si tienes workloads donde quieres mezclar modelos locales y Claude en el mismo pipeline.

*Fuente: [StartupCorners Trending](https://startupcorners.com/digest/devtools-digest-2026-09-06)*

### NousResearch/hermes-agent — General purpose agent framework

**Qué es:** Agent framework open source de NousResearch (conocidos por modelos Hermes fine-tuned). Se posiciona como agente de propósito general que "crece contigo" — manejo de memoria, context persistence, herramientas extensibles.

**Por qué te importa:** NousResearch tiene track record en fine-tuning para seguimiento de instrucciones. Si buscas un framework alternativo a CrewAI/LangGraph con mejor alineación a modelos open-source, vale evaluarlo.

**Acción sugerida:** Monitorear — está en etapa temprana pero el backing de NousResearch le da credibilidad técnica.

## ⚠️ Buyer Beware — Alerta de hype

**Todos hablan de los benchmarks de GPT-6 Astra, pero ojo porque...**

OpenAI reportó 99.9% en ARC-AGI 3 y 100% en ExploitBench usando su propio "Provider Adapter harness" — no los harnesses estándar de la comunidad. En el harness por defecto de ARC-AGI, el score cae a 62.7%. No es un detalle menor: es la diferencia entre "resolvió el benchmark del razonamiento general" y "resolvió su propia versión del benchmark".

El patrón se repite con ExploitBench. Cuando cada empresa empieza a publicar sus propios harnesses optimizados, los rankings de benchmark dejan de ser comparables.

Juzga Astra por sus demos prácticos y por el OSWorld 2.0 (que sí parece medido de forma más estándar, 72.6%). Todo lo demás, con un grano de sal.
