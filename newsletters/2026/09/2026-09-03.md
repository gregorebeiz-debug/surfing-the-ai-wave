## 🌊 The Wave Today — Noticias que mueven la aguja

### Claude Fable 5.1 y Mythos 5.1: Más barato, más capaz, menos refusals

Anthropic lanzó el 1 de septiembre sus modelos más avanzados hasta la fecha. **Fable 5.1** es la versión de producción con acceso general; **Mythos 5.1** es el mismo modelo subyacente con acceso restringido para organizaciones verificadas en ciberseguridad y ciencias de la vida.

Lo que importa operativamente: 25% menos costoso en workloads típicos, 75% de reducción en cache reads. Ventana de contexto de 1M tokens con 128K de output máximo. En benchmarks de coding: 55.8% en Terminal-Bench 4.0 vs. 42.0% del Fable 5 anterior — un salto significativo para tareas agentic de larga duración. Los safeguards de ciberseguridad ahora bloquean 60% menos falsos positivos, lo que significa menos interrupciones en flujos de trabajo.

Nueva Enterprise Frontier Safeguards tier para organizaciones que necesitan controles adicionales. El acceso a las capacidades de biología avanzada de Mythos 5.1 abrirá inscripción para científicos próximamente, en partnership con el gobierno de EE.UU.

### OpenAI anuncia Astra: el primer modelo con capacidades de ciberseguridad "críticas"

OpenAI publicó el 1 de septiembre su safety writeup para **Astra**, modelo todavía sin fecha de lanzamiento público. Es el primer modelo que supera su umbral "crítico" en el Preparedness Framework: puede encontrar vulnerabilidades zero-day y explotarlas sin instrucciones paso a paso de humanos.

El lanzamiento será por fases — primero a testers limitados vía el programa **Daybreak Blue**, donde las capacidades de ciberseguridad avanzada solo estarán disponibles para defensores aprobados. El acceso general no tendrá las capacidades más extremas de entrada.

La señal real: OpenAI está escalando deliberadamente el nivel de riesgo aceptado en sus releases. El precedente que sienta Astra — "lanzamos modelos que cruzan umbrales críticos pero con acceso restringido" — probablemente define cómo todos los labs manejarán la siguiente generación de modelos peligrosamente capaces. Si Astra llega al mercado general, el estándar de qué es "seguro" en IA cambia otra vez.

## 🛠️ Tool & Repo Watch — Herramientas y repos

### Claude Code Self-Hosted Environments — Beta pública para Team y Enterprise

Disponible desde el 6 de agosto en beta pública. Las organizaciones en planes Team y Enterprise pueden correr sesiones de Claude Code en su propia infraestructura con un único comando: `claude self-hosted-runner`. Aplica para sesiones web, mobile, desktop, terminal y scheduled routines.

**Por qué te importa:** Si usas Claude Code en proyectos con datos sensibles o con clients enterprise, esto cambia el mapa de lo que puedes ofrecerles. El código se ejecuta en tu infraestructura — pero los prompts y respuestas siguen viajando a Anthropic para inference. No es full air-gap: es control de compute, no de datos. Para proyectos personales sin compliance, no urgente. Para clients o proyectos enterprise: revisar ahora.

**Acción sugerida:** Explorar → [Anthropic blog](https://claude.com/blog/run-claude-code-sessions-on-your-own-compute)

### Bumblebee (Perplexity) — Scanner de supply chain que cubre tus MCP configs

Scanner open-source de solo lectura que verifica dependencias de npm, PyPI, Go modules, RubyGems, Composer — y también **configuraciones de MCP**, extensiones de editor y browser — contra releases comprometidos conocidos. Nunca ejecuta npm o pip, nunca lee código fuente, nunca hace llamadas de red durante el scan. Binario Go único, cero dependencias externas.

**Por qué te importa:** Usas Claude Code con MCP servers de terceros, y el ecosistema MCP está explotando en velocidad. Con eso viene riesgo de supply chain: un MCP server comprometido tiene acceso directo a tu filesystem y herramientas. Bumblebee corre en segundos y te dice si alguna de tus configs está en la lista de comprometidos. Corre esto contra tu setup hoy.

**Stars:** 4.8k+ | Licencia: Apache 2.0 | Open-sourced mayo 2026

**Acción sugerida:** Instalar → [GitHub](https://github.com/perplexityai/bumblebee)

### n8n — Soporte nativo MCP (actúa como client y como server)

n8n ahora puede actuar tanto como **MCP Client** (llamar a herramientas externas vía MCP) como **MCP Server** (exponer sus propios workflows como tools para otros agentes). Task Runners ahora activos por defecto en todos los nodos Code: las ejecuciones corren en procesos aislados, sin riesgo de crashes por loops infinitos o memory leaks.

**Por qué te importa:** Esto convierte a n8n en un nodo de integración bidireccional en cualquier arquitectura MCP. Tus workflows existentes de n8n pueden ser llamados directamente desde Claude Desktop, Claude Code, u otros agentes — sin código adicional. Es el puente entre tu automatización existente y el ecosistema de agentes Claude. Si tienes workflows de n8n que hacen operaciones útiles (scraping, envío de emails, consultas a APIs), ahora puedes exponerlos como tools MCP y que Claude los llame directamente.

**Acción sugerida:** Explorar el nodo MCP en tu instancia → [n8n features](https://ciphernutz.com/blog/n8n-workflow-automation-latest-features)
