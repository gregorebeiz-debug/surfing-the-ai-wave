### 1. Acción requerida antes del 8 de junio: el Agent SDK ya tiene su propio pool de créditos

La noticia más urgente de la semana. A partir del **15 de junio**, el uso del **Claude Agent SDK**, `claude -p`, **Claude Code GitHub Actions**, y todas las apps de terceros construidas sobre el Agent SDK (OpenClaw, Conductor, Zed, Jean) dejarán de consumir los límites de tu suscripción interactiva y migrarán a un nuevo **"Agent SDK Credit Pool"** separado.

**Qué cambia en números:**
- Pro plan: **$20/mes** de crédito de Agent SDK
- Max 5x: **$100/mes**
- Max 20x: **$200/mes**

Los créditos se cobran a precios de API estándar. Cuando se agotan, las solicitudes automatizadas se detienen **completamente** — sin rollover, sin fallback automático, sin aviso previo — a menos que hayas activado el "overflow billing" manualmente.

El diagnóstico crítico aquí es de doble filo: para usuarios con uso moderado de Agent SDK, el nuevo pool puede ser suficiente e incluso más predecible que el modelo actual. Pero para cualquiera que tenga pipelines pesados de `claude -p` o agentes corriéndose en GitHub Actions varias veces al día, $20 en Pro se va a evaporar en días. El 8 de junio Anthropic enviará un email para reclamar los créditos iniciales — ponlo en el calendario ya.

**Acción:** Audita tu uso actual de `claude -p`, Agent SDK y GitHub Actions. Si supera ~100K tokens/mes en modo programático, considera subir a Max o activar overflow billing antes del 15.

## 🛠️ Tool & Repo Watch — Herramientas y repos

### Claude Code — Actualización de junio: agentes, MCP y métricas más robustas

Las actualizaciones de junio consolidan mejoras de calidad-de-vida que impactan directamente flujos de trabajo con múltiples agentes. Lo más relevante:

- **`claude agents --json` con campo `waitingFor`** — Muestra exactamente en qué está bloqueada una sesión en espera (ej. un permission prompt pendiente). Elimina el guessing cuando un pipeline multi-agente se congela.
- **Slash commands en autocomplete** — Ahora rellenan el prompt en lugar de ejecutarse automáticamente al hacer click; más control en sesiones interactivas.
- **OTEL_RESOURCE_ATTRIBUTES como labels en métricas** — Permite slicear usage metrics por dimensiones custom (equipo, repo, cliente). Útil si facturas por proyecto o monitoreas costos granularmente.
- **MCP server connections más estables** — Mejor parallel tool handling y fixes en conexiones MCP; menos drops en pipelines de larga duración.
- **Remote Control como pill persistente** — Aparece en el footer en lugar del mensaje de startup; menos ruido visual.

**Por qué te importa:** Si usas Claude Code con múltiples sub-agentes o tienes pipelines que se congela sin explicación, `waitingFor` es la feature que necesitabas. Las mejoras de MCP reliability afectan directamente cualquier setup con servidores MCP custom.

**Suggested action:** Update. → [Changelog](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md) | [Releasebot](https://releasebot.io/updates/anthropic/claude-code) [Claude Ecosystem]

## ⚠️ Buyer Beware — Alerta de hype

**El billing split del Agent SDK suena razonable — pero el math no cuadra en Pro**

Anthropic presenta el cambio como "dar a los desarrolladores más claridad sobre su uso programático". Técnicamente correcto, pero el subtext es otro: estaban subsidiando uso de Agent SDK dentro del modelo de suscripción plana, y ese subsidio se acaba.

$20/mes en créditos API para un plan Pro cubre aproximadamente 1-2 millones de tokens a precios de Sonnet — que en una semana de uso moderado de Claude Code con GitHub Actions puede quedarse corto. El modelo favorece fuertemente a Max (5x/$100) para desarrolladores que automaticen en serio. Si hoy usas Claude Code + Agent SDK dentro de Pro asumiendo que el uso es "ilimitado", ese supuesto desaparece el 15 de junio. Haz el cálculo antes, no después.
