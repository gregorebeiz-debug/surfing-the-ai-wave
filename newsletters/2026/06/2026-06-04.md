El Claude que usas hoy no es el mismo que usarás después del roadshow. Observa cómo cambia el pricing y los límites de uso en los próximos meses.

### Claude Code: Dynamic Workflows + auto-carga de plugins

Esta semana llegó la actualización más relevante para quien usa Claude Code como herramienta de trabajo. Dos cambios de fondo:

**Dynamic Workflows** (research preview, planes Enterprise/Team/Max): Un orquestrador puede spawnear cientos de sub-agentes en paralelo, cada uno con su propio context window, y agregar los resultados en un output coherente. Caso de uso demostrado: migraciones de codebase a escala —cientos de miles de líneas, de kickoff a merge, con el test suite como criterio de calidad. No es hype de demo. Es el workflow que hace que una tarea de semanas tome horas.

**Auto-carga de plugins desde `.claude/skills`**: Ya no hace falta un marketplace ni configuración manual. Claude Code detecta y carga plugins automáticamente. Además `claude plugin init <n>` scaffoldea un plugin nuevo, y hay autocomplete para argumentos `/plugin`. Sumado al nuevo campo `agent` en `settings.json` para dispatched sessions —y a la posibilidad de `--agent <n>` para overrides por sesión— la arquitectura multi-agente de Claude Code está madurando rápido.

Otras mejoras de Opus 4.8 integradas en Claude Code: effort controls (más pensamiento = mejor respuesta, menos = más velocidad); 4x más honesto sobre bugs no reportados que Opus 4.7; precio de Fast mode reducido a 1/3 del costo anterior.

**Por qué importa:** Si construyes agentes o automatizaciones complejas con Claude Code, dynamic workflows es el cambio que estabas esperando. La combinación plugins automáticos + multi-agente paralelo + effort controls convierte Claude Code en un sistema de orquestación serio, no solo un coding assistant.

### Microsoft Build 2026: todo converge en agentes

El 2 de junio, Microsoft entregó su mensaje unificado: Windows, Azure, GitHub y Copilot son ahora una sola plataforma de agentes autónomos. Los anuncios concretos:

- **GitHub Copilot desktop app** (preview para Windows/Mac/Linux): Interfaz nativa para gestionar agents y workflows. Workspace Agents escribe código across múltiples archivos, corre tests, y abre PRs de manera autónoma con review gates humanos.
- **MAI-Thinking-1 y MAI-Code-1**: Dos nuevos modelos propios de Microsoft. MAI-Code-1 está optimizado para GitHub y VS Code.
- **Microsoft IQ**: Capa de contexto empresarial que agrega M365 signals (Work IQ), datos estructurados de Fabric (Fabric IQ) y grounding web (Web IQ) para alimentar todos los agentes.
- **Rayfin SDK**: Conecta agentes como servicios backend. Para construir pipelines de agentes que exponen APIs.

**Por qué importa:** Copilot Workspace Agents rivaliza directamente con Claude Code en el espacio de agentic coding. Pero hay una diferencia crítica: Copilot sigue atado al ecosistema Microsoft y sus modelos propios (MAI) no tienen benchmark público contra Opus 4.8. Por ahora, Claude Code lleva ventaja en reasoning profundo y honestidad de outputs. Monitorea MAI-Code-1 cuando haya datos comparativos.

## ⚠️ Buyer Beware — Alerta de hype

Todos hablan del **Microsoft Build 2026 y los Copilot Workspace Agents**, pero ojo porque:

Los demos mostraron agents que escriben código, corren tests y abren PRs "autónomamente" — lo mismo que Claude Code lleva meses haciendo con dynamic workflows. La diferencia está en el modelo subyacente: MAI-Code-1 es nuevo y sin benchmarks públicos. El GitHub Copilot app todavía es "technical preview" y requiere suscripción activa a Copilot. La capa Microsoft IQ que "alimenta a todos los agentes con contexto empresarial" es básicamente RAG sobre M365 con un nombre de marketing más atractivo.

No descartes el ecosistema Microsoft —tiene ventaja en entornos enterprise con M365— pero no migres de Claude Code hasta ver datos comparativos reales de MAI-Code-1 vs Opus 4.8 en tasks complejas.
