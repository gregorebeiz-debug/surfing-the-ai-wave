### Claude Mythos se asoma a Claude Code — y es hoy

El modelo hasta ahora completamente restringido de Anthropic, `claude-mythos-1-preview`, apareció el 25 de mayo en strings de la UI de Claude Code y Claude Security, y brevemente como toggle visible antes de desaparecer. La estrategia de rollout que se perfila: Mythos 1 como capability gated dentro de productos enterprise primero (Claude Code, Claude Security), antes de cualquier acceso público general. El modelo promete razonamiento de código y análisis de vulnerabilidades sustancialmente superior — los ~50 partners del programa Glasswing ya lo usaron para encontrar más de 10,000 vulnerabilidades de severidad alta o crítica en software ampliamente usado. Los controles de misuse siguen sin resolverse, razón por la que Anthropic revirtió su postura inicial de "no habrá release público" hacia esta apertura gradual. Lo que te importa concretamente: si usas Claude Code Pro o Enterprise, es probable que seas de los primeros en acceder.

## 🏄 Deep Dives — Vale la pena explorar directamente

### Claude Code — Agent View, /goal Command y Background Sessions

Las actualizaciones de la Semana 20 de Claude Code son directamente accionables para tu flujo diario. **Agent View** abre una pantalla unificada para todas tus sesiones: qué está corriendo, qué espera tu input, qué terminó. **El comando /goal** mantiene a Claude trabajando en un objetivo a través de múltiples turns hasta que una condición de completación se cumple — sin que tengas que re-lanzar manualmente. **Fast mode** ahora usa Opus 4.7 por defecto. Las **background sessions** (iniciadas con `claude --bg`) aparecen junto a las interactivas con etiqueta `bg`. El menú **Rewind** agrega "Summarize up to here" para comprimir contexto en sesiones largas. Nuevos flags para `claude agents`: `--add-dir`, `--settings`, `--mcp-config`, `--model`, `--effort`, `--permission-mode`.

**Por qué te importa:** Agent View + /goal reducen la fricción operacional real de Claude Code: menos babysitting de sesiones, más delegación autónoma. Los flags de `claude agents` son especialmente útiles si estás construyendo pipelines multi-agent donde necesitas configurar cada sesión dispatched con su propio modelo, settings o permisos.

[Leer changelog completo](https://code.claude.com/docs/en/whats-new) | [Releasebot](https://releasebot.io/updates/anthropic/claude-code) [Claude Ecosystem]

### Claude Managed Agents — MCP Tunnels y Self-hosted Sandboxes

Anthropic publicó el 19 de mayo dos features para Managed Agents. **Self-hosted sandboxes** (public beta): ejecuta tool execution en compute propio o de partners, sin que las herramientas corran en infraestructura de Anthropic — control total sobre el entorno de ejecución. **MCP Tunnels** (research preview): conecta agents a servidores MCP internos (bases de datos privadas, APIs internas, knowledge bases, ticketing systems) sin exponerlos a internet. El gateway es un proceso ligero con una única conexión saliente — sin reglas de firewall entrantes, tráfico cifrado end-to-end, credenciales controladas en el boundary de red en vez de dentro del contexto del agent. Se administra desde workspace settings en Claude Console.

**Por qué te importa:** Si construyes agents que necesitan acceder a datos privados — tu CRM, repositorios internos, APIs propias — MCP Tunnels es la arquitectura correcta. Mueve el problema de seguridad del prompt al network layer. Esto transforma cuáles casos de uso enterprise son viables sin sacrificar security posture.

[Claude Blog](https://claude.com/blog/claude-managed-agents-updates) | [InfoQ](https://www.infoq.com/news/2026/05/claude-mcp-tunnels/) | [VentureBeat](https://venturebeat.com/orchestration/claude-agents-can-finally-connect-to-enterprise-apis-without-leaking-credentials) [Claude Ecosystem]

### n8n — Microsoft Agent 365 Trigger y Human-in-the-Loop

n8n lanzó en mayo el **Microsoft Agent 365 Trigger**: tus workflows de n8n se convierten en agentes con identidad propia dentro de Microsoft 365 — con email address propio, mencionables con @ en Teams, con permisos en SharePoint como cualquier teammember. La construcción es directa: system prompt + herramientas + MCP servers + sub-workflows como tools. Paralelamente, las mejoras de **Human-in-the-Loop** permiten agregar pasos de revisión humana en conexiones de AI Agent a tools con control granular: quién aprueba, qué mensaje recibe, qué acciones están disponibles, qué botones se muestran.

**Por qué te importa:** n8n ya consume MCP servers y expone workflows como MCP tools — lo convierte en un hub agentic de primera clase compatible con tu stack de Claude Code. Microsoft Agent 365 Trigger es relevante si tienes clientes o workflows que viven en el ecosistema Microsoft. Y Human-in-the-Loop bien implementado es la diferencia entre un agent que produce valor y uno que produce errores costosos sin intervención.

[n8n Docs](https://docs.n8n.io/release-notes/) | [n8n Blog sobre agentes 2026](https://blog.n8n.io/we-need-re-learn-what-ai-agent-development-tools-are-in-2026/) [AI Automation]
