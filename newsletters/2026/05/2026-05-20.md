### Claude Code: Agent View, /goal, y rate limits duplicados

Anthropic entregó esta semana un paquete de actualizaciones significativas a Claude Code: `claude agents` abre una pantalla de supervisión unificada para todos los agentes corriendo, bloqueados o completados (Research Preview disponible hoy en Pro/Max/Team/Enterprise). El comando `/goal` permite a Claude trabajar entre turnos hasta que una condición de completitud se cumple — sin interrupciones de tu parte. Fast mode ahora usa Opus 4.7 por defecto. Los rate limits en Claude Code se duplicaron y los de la API de Opus también subieron. Se agregó `/resume` para sesiones background iniciadas con `claude --bg`.

**Por qué importa:** Agent View es la interfaz de control que faltaba para orquestar múltiples agentes simultáneos desde una sola pantalla. Con `/goal` podés delegar objetivos complejos de múltiples pasos y desentenderte hasta que Claude termine. Si usás Claude Code como principal herramienta de trabajo, habilitá Agent View hoy.

### Universidad de Melbourne — "Do We Still Need LangGraph?"

Investigación de abril 2026 que encontró que para la mayoría de tareas procedurales, los frameworks de orquestación externa (LangGraph, CrewAI, AutoGen) **empeoran** el rendimiento de los agentes comparado con llamadas directas al SDK del modelo. El paper identifica overhead de abstracción, latencia de contexto y pérdida de control de estado como causas principales.

**Por qué leer:** Si estás eligiendo arquitectura para tu próximo agente — LangGraph vs Claude SDK directo vs n8n — este paper da argumentos concretos para defender la simplicidad. No dice que los frameworks no sirvan, dice que se sobreaplican.

## ⚠️ Buyer Beware — Alerta de hype

**Todos hablan de LangGraph, CrewAI y AutoGen como la solución para construir agentes — pero ojo.** La investigación de la Universidad de Melbourne (abril 2026) encontró que para tareas procedurales típicas, usar estos frameworks de orquestación *empeora* el rendimiento comparado con llamadas directas al SDK del modelo. El paper atribuye esto al overhead de abstracción, latencia de contexto y pérdida de control de estado fino. La industria responde que son imprescindibles para workflows complejos de producción — y probablemente ambos tengan razón. El problema es que se presentan como la solución por default cuando deberían ser la solución por excepción. Si tu próximo agente no requiere estado compartido entre múltiples agentes o rollback condicional, Claude SDK directo puede ser más rápido, más barato y más predecible.
