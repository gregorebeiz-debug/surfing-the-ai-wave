**Por qué importa:** Anthropic siendo pública cambia las dinámicas competitivas con OpenAI y Google. Más liquidez puede significar más inversión en Claude Code, más MCP servers, más infraestructura. También puede significar más restricciones de uso impulsadas por compliance. Vigilar con atención.

### Claude Code bloquea recreación de videojuegos existentes

A partir del 27 de octubre, Claude Code comenzó a rechazar solicitudes de recrear juegos existentes específicos. El cambio es una regla server-side bajo el flag `tengu_heron_brook` — no es configurable por el usuario. Anthropic confirmó que actualizó el modelo Opus 5.5 para "orientar" a Claude Code a alejarse de "recrear el juego específico de alguien más", citando su política de uso sobre infracción de IP.

Lo que no está claro: el límite entre un juego en un género y una recreación de un juego específico. Usuarios reportan rechazos en código legítimo de sus propios títulos, en crash dumps y en anti-cheat. Addy Osmani (Anthropic) pidió que le envíen casos donde Claude rechace trabajo legítimo del usuario.

**Implicación directa:** Si usas Claude Code para construir prototipos de juegos, espera fricciones. La llamada directa a la API sin el client de Claude Code no recibe esta sección del system prompt — lo que significa que el mismo modelo sigue disponible vía API. Esto no es una restricción del modelo, es una restricción del cliente.

*Fuentes: [Game Developer](https://www.gamedeveloper.com/programming/anthropic-appears-to-have-ordered-ai-tool-claude-to-stop-remaking-video-games), [Tom's Hardware](https://www.tomshardware.com/tech-industry/artificial-intelligence/anthropic-confirms-new-claude-code-limits-to-prevent-game-cloning-users-report-opus-5-5-is-also-actively-blocking-reverse-engineering-tasks)*

## 🔧 Tool & Repo Watch — Herramientas y repos

### `JuliusBrussee/caveman` — 117K ★ — Skill que reduce 65-75% de tokens en agentes de código

Un skill + proxy para coding agents que comprime el output haciendo que el modelo "hable como un cavernícola" — sin fluff, sin explicaciones largas, solo código y directivas mínimas. El resultado reportado: 65-75% menos output tokens manteniendo precisión técnica. Un benchmark independiente reportó 33.2% menos input tokens en 54 runs con 18/18 pruebas pasadas. Incluye `/caveman-stats` para monitorear ahorro por sesión en Claude Code.

**Por qué te importa:** Si usas Claude Code diariamente para construir agentes y automatizaciones, esto es directamente dinero. A los precios actuales de Opus 5.5, una reducción del 65% en tokens de output cambia significativamente el costo mensual de proyectos complejos. Caveat: las compresiones afectan las explicaciones alrededor del código, no el código mismo — útil para workloads de producción, puede reducir legibilidad en pares o revisiones de código.

**Acción:** Install. Evalúa con `/caveman-stats` después de una sesión de trabajo normal.

→ [GitHub](https://github.com/JuliusBrussee/caveman) [Claude Ecosystem]

### `deepseek-ai/deepseek-harness` — 270K ★ — Framework de agentes plugin-first

DeepSeek Harness (dsh) es un framework de agentes donde literalmente todo es un plugin — incluyendo el modelo. Construido sobre Cordis (meta-framework de plugins en TypeScript), el core solo maneja carga/descarga de plugins y dependencias. Arquitectura MIT-licensed, lanzable vía `npx @deepseek-ai/dsh web` en localhost:3080. Aún en developer preview con breaking changes esperados.

**Por qué te importa:** Si experimentas con agentes multi-modelo o quieres una alternativa a LangGraph/CrewAI que no esté atada al stack de LangChain, dsh ofrece una arquitectura más limpia a nivel de composición. El hecho de que el modelo sea un plugin significa que puedes conectar Claude, GPT, o modelos locales via Ollama sin cambiar la lógica del agente. Espera hasta versión estable antes de producción.

**Acción:** Monitor. Revisa el changelog antes de experimentar en proyectos reales.

→ [GitHub](https://github.com/deepseek-ai/deepseek-harness) [AI Agents]

## ⚠️ Buyer Beware — Alerta de hype

**El número de estrellas de caveman no es lo que parece.** Múltiples directorios listan el repo con conteos inconsistentes entre sí. El benchmark de 33.2% de reducción en input tokens viene del propio proyecto, no de una auditoría independiente. Los 65-75% de reducción en output tokens aplican principalmente al "connective tissue" — explicaciones, planes, summaries — no al código mismo. Úsalo, pero mide tus propios resultados antes de aplicarlo globalmente a todos tus proyectos. El riesgo real: repositorios con comentarios tipo caveman son difíciles de mantener para otros humanos.
