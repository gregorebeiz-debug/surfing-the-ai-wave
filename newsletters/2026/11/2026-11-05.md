### Anthropic Advierte: Claude Escribe Su Propio Sucesor — RSI a la Vista

En su S-1/A enmendado presentado ante la SEC esta semana, Anthropic hizo una revelación que pocos esperaban leer en un documento de IPO: la compañía puede estar cerca de su propio umbral interno para **recursive self-improvement (RSI)** — el punto donde una IA puede acelerar el desarrollo de modelos de forma autónoma. Claude actualmente escribe más del **90% del código mergeado en las bases de código de Anthropic** (a septiembre de 2026, vs. el 80%+ reportado en mayo de 2026). Ningún modelo actual ha cruzado el umbral, pero Anthropic está considerando actualizar su Responsible Scaling Policy para mantener supervisión humana sobre el diseño de modelos frontier.

Lo crítico aquí no es el hype de RSI — varios académicos (incluyendo al profesor de Georgia Tech Mark Riedl) lo llaman exagerado y señalan que el filing no dice que hayan construido una IA que se mejora sola. Lo que importa es el dato concreto: **el ciclo donde cada modelo ayuda a construir el siguiente se está cerrando**, y eso tiene consecuencias reales para el ritmo de lanzamientos futuros de Claude — que es el modelo en el que tú construyes y dependes a diario.

### Anthropic IPO: S-1 Presentado, $17B/Trimestre, De Regreso a Pérdidas

Anthropic presentó su S-1 ante la SEC el **26 de octubre de 2026**, marcando el inicio formal del proceso de IPO. La pregunta importante cuando cotice es si la presión de los mercados empieza a comprimir los ciclos de lanzamiento y la inversión en safety. Eso afecta directamente qué tan rápido (y qué tan bien) evolucionará Claude.

### Claude Code 2.1.318 — Lazy Loading de Herramientas MCP

La última versión de Claude Code (2.1.318, primero visto el 4 de noviembre) introduce **lazy loading de MCP tools**: las definiciones de herramientas de servidores MCP conectados ya no se cargan todas en contexto al inicio de la sesión. Esto reduce el tamaño de contexto consumido por definiciones de herramientas que nunca se usan en un turno dado. Adicionalmente, se corrigió un bug donde subagents no podían usar herramientas de servidores MCP que terminaban de conectarse después de que el subagent había iniciado — y se solucionó la desconexión de servidores locales (stdio) en Claude Desktop tras el primer turno.

Ambos fixes apuntan a los problemas de estabilidad más reportados por power users de Claude Code con múltiples servidores MCP conectados simultáneamente.

### Simon Willison — LLM CLI 0.37 / 0.37.1
*CLI para trabajar con LLMs desde terminal*

El CLI de Simon Willison para invocar modelos desde la línea de comandos lanzó versión 0.37 (Nov 2) y bugfix 0.37.1 (Nov 3). Willison señaló que casi todos los fixes de este release fueron generados con asistencia de IA — un meta-punto sobre el estado actual del desarrollo. Esta versión agrega soporte para los modelos **GPT-6 Sol y Luna** de OpenAI.

**Por qué te importa:** Si tienes scripts de automatización que necesitan llamar a un LLM sin montar un cliente de API completo, `llm` es la herramienta más limpia que existe para eso. Compatible con Claude, GPT-6, Gemini, y modelos locales. También soporta el patrón de shebang en archivos de texto para scripts ad-hoc. Perfecto para el tipo de pipelines rápidos que construyes en bash o Python.

**Acción sugerida:** Explorar si aún no lo usas en tus pipelines → [simonwillison.net](https://simonwillison.net/2026/Nov/2/llm/)

### Claude Haiku 5.5 — El modelo pequeño para trabajo de alto volumen
*Lanzado Oct 7, 2026 | Anthropic*

El modelo más rápido del ecosistema Claude. Diseñado explícitamente para **summarización, subagents y browser use** — casos de uso donde el volumen de llamadas es alto y la tarea no requiere el razonamiento completo de Sonnet u Opus.

**Por qué te importa:** Si tienes pipelines multi-agente en CrewAI, LangGraph o Claude Code donde los subagents hacen tareas repetitivas (clasificar items, extraer datos estructurados, verificar outputs parciales), estás probablemente sobredimensionando con Sonnet. Haiku 5.5 baja dramáticamente el costo por llamada sin sacrificar calidad en tareas delimitadas. El 90% de los subagents en un pipeline típico no necesita el modelo más grande.

**Acción sugerida:** Evaluar costo/calidad para reemplazar Sonnet en subagents de bajo costo → [Anthropic](https://www.anthropic.com/news/announcements)
