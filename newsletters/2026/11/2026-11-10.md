### Claude Fable 5.2 y Mythos 5.2: Anthropic sube el techo de nuevo

Anthropic lanzó ayer (9 de noviembre) **Claude Fable 5.2** y **Claude Mythos 5.2**, sus modelos más capaces para trabajo técnico profundo. Los cambios más relevantes:

- Hasta **30% más rápidos** que sus predecesores (Fable 5.1 / Mythos 5.1)
- **Fast Mode** disponible en la API de mensajes — a precio de Fable 5.2
- **1 millón de tokens** de contexto, con adaptive thinking siempre activo
- Context window de reasoning configurable: low / medium / high / xhigh / max (default: high)
- **Fable 5.2** no requiere aprobación de acceso en la Claude API
- **Mythos 5.2** es el mismo modelo base pero con restricciones relajadas para ciberseguridad y ciencias de la vida — acceso verificado requerido (excepto Enterprise via Claude Security)
- Pricing API: ~$8/M tokens de entrada, $40/M de salida — sin cambio vs. anterior
- Model IDs: `claude-fable-5-2`, `claude-mythos-5-2`

**Por qué importa:** Si usas Claude Code con modelo configurado, verás mejoras de velocidad sin cambiar nada. Para tus agentes que usan la API directamente, Fast Mode es ahora una opción real de optimización de costos en llamadas de alta frecuencia. Fable 5.2 debería ser tu nuevo default si ya usas la API.

*Fuentes: [Anthropic Blog](https://www.anthropic.com/news/announcements), [Platform Docs](https://platform.claude.com/docs/en/models/fable-5-2/whats-new-fable-5-2)*

### Perplexity Teammates: Agentes persistentes con su propio escritorio

El 5 de noviembre, Perplexity lanzó **Teammates** — preview para suscriptores Max ($200/mes). No son conversaciones: son agentes que corren 24/7, con su propio navegador, escritorio y un hilo nunca-cerrado. Un Teammate puede monitorear una campaña mientras otro investiga competidores o trabaja en código. El producto se construye sobre Perplexity Computer (lanzado en febrero).

Restricciones actuales: solo web, no iOS, no Enterprise por defecto. Los heavy tasks consumen créditos de uso más rápido.

**Por qué importa:** Perplexity apuesta por el mismo modelo de agentes persistentes que tú ya construyes manualmente. La diferencia es que ellos abstraen toda la infraestructura (escritorio, browser, memoria de hilo). Si tu stack agent actual requiere mucha orquestación manual, Teammates es un punto de referencia útil — no como reemplazo sino como benchmark de UX.

*Fuentes: [TechRepublic](https://www.techrepublic.com/article/news-perplexity-teammates-ai-agents-pricing-features/), [Let's Data Science](https://letsdatascience.com/news/perplexity-launches-teammates-persistent-ai-agents-for-max-s-704b7a36)*

## 🔧 Tool & Repo Watch — Herramientas y repos

### Claude Code v2.1.319 — MCP tasks en background + nuevo control de permisos

**MCP background tasks (el cambio más importante):** Cuando un servidor MCP lanza una tool call de larga duración, Claude Code ahora la mueve al background y continúa trabajando; el resultado llega cuando termina. Variable de control: `CLAUDE_CODE_DISABLE_MCP_TASK_BACKGROUND=1` para comportamiento síncrono.

**Nuevo setting de permisos:** `permissions.denyInsteadOfPrompting` — en lugar de pausar esperando tu confirmación, deniega directamente. Crítico para runs desatendidos (como esta misma routine).

**Cambio en skills sandbox:** Con el Bash sandbox activo, los skills en carpetas `.claude/skills/` debajo del directorio de inicio solo cargan si arrancas Claude Code desde ahí o navegas con `/cd`.

**Por qué te importa:** Usas Claude Code diariamente y ya tienes MCP servers configurados. El background task support elimina uno de los friction points más molestos — ya no tienes que esperar que un MCP call largo bloquee tu sesión. El `denyInsteadOfPrompting` es exactamente lo que necesitas para tus sessions automáticas. **Actualiza si no lo has hecho.**

Versión actual: v2.1.319 | [Changelog oficial](https://code.claude.com/docs/en/changelog.md) | Acción: **Actualizar ahora**

### Cursor Build Live Apps — De código a URL pública en un clic

Cursor lanzó el 5-6 de noviembre la función **Build Live Apps**: el agente de cloud de Cursor puede ahora scaffoldear una web app, provisionar Postgres con Cursor SSO, correr checks de seguridad, y desplegar con una URL pública — todo desde dentro del editor, en planes pagos con cloud agents.

Casos de uso documentados: herramientas de operaciones, apps de onboarding interno, registros de eventos.

**Por qué te importa:** Si usas Cursor para desarrollo web con AI, esto comprime el ciclo prototype → deploy a minutos. Útil para MVPs, herramientas internas y demos de cliente. Ojo con el warning de los análisis: **no reemplaza una configuración de producción real** — el code que genera puede acumular deuda técnica y de seguridad rápido si lo confundes con prod.

Acción: **Explorar** (prueba con un proyecto interno no crítico) | [Cursor Changelog](https://cursor.com/changelog/build-live-apps)

### LangGraph 1.2.19 — Sandbox integrations para ejecución segura de código

La versión actual de LangGraph (1.2.19, MIT) suma **sandbox integrations** vía plugins: `langchain-modal`, `langchain-daytona`, `langchain-runloop`. Permite ejecutar código generado por agentes en entornos aislados en lugar de directamente en el host.

**Por qué te importa:** Si construyes agentes con LangGraph que ejecutan código (común en tus pipelines de automatización), estos plugins eliminan el riesgo de ejecución en el host local. Modal en particular es una opción interesante si ya tienes workflows GPU. Si tus agentes usan el Claude SDK directamente sin LangGraph, **no te afecta**. Si tienes agentes con LangGraph en producción, revisa el changelog antes de actualizar.

Stars: ~180k (estimado) | [PyPI](https://pypi.org/project/langgraph/) | Acción: **Monitor**
