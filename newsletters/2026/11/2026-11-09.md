### Claude Code 2.1.319: MCP tasks van al background

La versión 2.1.319 (publicada el 6 de noviembre) redefine cómo Claude Code interactúa con servidores MCP. Cambios clave: (1) los tool calls de MCP ahora se ejecutan en segundo plano sin bloquear la conversación; (2) nueva setting `permissions.denyInsteadOfPrompting` que rechaza automáticamente tool calls que requerirían intervención humana; (3) fix para servidores MCP con handshake legacy que fallaban con el nuevo protocolo; (4) nuevo comando `/claude-api latency-optimize`; (5) variable `CLAUDE_CODE_DISABLE_FEATURE_FLAGS` para parar feature-flag fetching en entornos controlados.

**Por qué importa:** El deny-instead-of-prompt es exactamente lo que se necesita para runs autónomos y desatendidos. Si tus agentes usan MCP servers con operaciones largas (Firecrawl, GitHub, Gmail), ya no frenan el flujo. Actualización crítica si usas Claude Code en automatizaciones.

*Fuentes: [ai-tldr.dev](https://ai-tldr.dev/releases/anthropic-claude-code-2-1-319/), [Releasebot](https://releasebot.io/updates/anthropic/claude-code)*

### DeepSeek Harness — Agent runtime open-source, 1.54M DAU

Runtime de agentes lanzado el 13 de agosto bajo licencia MIT. Arquitectura plugin-first desde el core: todo el comportamiento del agente está expuesto como plugins toggleables y editables. No hay lock-in de modelo — puedes usar Claude, DeepSeek, o cualquier otro LLM. Reporte del 4 de noviembre: 1.54M usuarios activos diarios, 5.48M mensuales, 35K plugins de terceros. Construido sobre Cordis meta-framework.

**Por qué te importa:** No es otro LangGraph con una capa de plugins encima. Es plugin-first desde el diseño, lo que significa menos reescritura si cambias de modelo. Si construyes agentes multi-modelo o quieres una alternativa más composable a LangGraph/CrewAI, esta arquitectura vale la pena entender antes de que llegue al mainstream hispanohablante.

**Acción sugerida:** Explorar — revisar GitHub y docs. No migrar todavía, pero evaluar arquitectura.

🔗 [BetterStack Guide](https://betterstack.com/community/guides/ai/deepseek-harness-plugin.md) | [FourWeekMBA](https://fourweekmba.com/ai-deepseeks-ai-agent-hits-1-54m-daily-users-and-5-5m-a-month/)

### GPT-6 Cyber (OpenAI) — Modelo ofensivo de seguridad

Lanzado el 5 de noviembre con acceso restringido a clientes Daybreak Red aprobados (authorized pentesting). Score: 48.5% en ExploitGym (+16.4pp vs GPT-5.6 Cyber). Reporta haber encontrado 81 vulnerabilidades en Firefox y 948 bugs en Linux. Versión especializada de GPT-6 Astra. Scope adherence: 0.07% de honeypot runs cruzaron límites vs 5.51% del modelo anterior.

**Por qué te importa:** No es para tu workflow. Es señal del estado del arte en AI para seguridad ofensiva. Si construyes agentes con acceso a sistemas o pipelines de CI/CD, el threat landscape que estos modelos definen — junto con adversarios que los usan — te afecta directamente. Monitorear para entender los riesgos que tus propios agentes enfrentan.

**Acción sugerida:** Info only — monitorear evolución del mercado de AI security.

🔗 [eSecurity Planet](https://www.esecurityplanet.com/news/news-openai-gpt-6-cyber-security-benchmarks/)

### 131 paquetes npm envenenados — Supply chain attack directo a AI tooling

CrowdStrike reporta que el 87% de las amenazas en registros de software en H1 2026 fueron paquetes npm. Se identificaron 131 paquetes AI envenenados. Adicionalmente, detectaron SANDWORM_MODE: un worm de supply-chain que apunta específicamente a desarrollo AI-asistido y pipelines CI/CD.

**Por qué te importa:** `npm install @anthropic-ai/claude-code` es parte de tu workflow diario. Si alguno de tus proyectos instala paquetes AI de terceros sin auditoría — MCP servers de terceros, integraciones n8n, herramientas de agentes — esto es un vector de ataque real. No es FUD genérico.

**Acción sugerida:** Instalar acción defensiva — correr `npm audit` en proyectos activos, verificar provenance de cualquier paquete AI de terceros.
